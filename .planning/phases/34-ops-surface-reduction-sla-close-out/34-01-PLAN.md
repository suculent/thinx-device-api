## Research resolutions carried into this plan (research disabled — resolved by the planner, 2026-10-09)

1. **Access-log fields (D-02)** — Traefik v3.7 reference (`reference/install-configuration/observability/logs-and-accesslogs`): no RequestQuery field exists; RequestPath = request URI (carries the query), RequestLine = RequestMethod + RequestPath + RequestProtocol (also carries it). Both are dropped. Header fields default to `drop`. `--log.level` accepts TRACE/DEBUG/INFO/WARN/ERROR/FATAL/PANIC.
2. **Swarm provider Docker API calls (D-08)** — v3.7 `pkg/provider/docker/pswarm.go`: ServerVersion, ServiceList, NetworkList (`scope=swarm`), TaskList (`service=<id>`, `desired-state=running`), NodeInspect (per task with a node id); ticker polling, no Info, no Events. Plus `/_ping` (HEAD, GET fallback) from client API-version negotiation.
3. **Proxy image (D-05)** — no socket-proxy in the DHI catalog; `wollomatic/socket-proxy` (Go, distroless): flags `-allowfrom` (default 127.0.0.1/32 — MUST be set), `-allowGET`/`-allowHEAD` (regex anchored automatically, matched against the URL path only, query excluded), `-listenip` (default 127.0.0.1 — MUST be 0.0.0.0), `-proxyport` 2375, `-allowhealthcheck`, `-watchdoginterval`, `-stoponwatchdog`, `-shutdowngracetime`, `-loglevel`. Blocked: 403 `forbidden IP`, 405 `method not allowed`, 403 `path not allowed`, each logged as a blocked request. Hostname allowfrom entries are re-resolved per request, but a swarm service name resolves to the VIP, so the pinned-subnet CIDR is used.
4. **`docker service create --health-cmd` is always shell-form** and the proxy image is distroless — no `--health-cmd` is passed; `-allowhealthcheck` is set so an image-defined exec-form HEALTHCHECK (if the image has one — record `docker image inspect --format '{{json .Config.Healthcheck}}'`) works; liveness is otherwise covered by `-watchdoginterval=30 -stoponwatchdog` (the proxy exits if the socket disappears and swarm restarts it) and the D-10 gates.
