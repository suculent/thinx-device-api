<interfaces>
New module services/console/vue/src/store/logPaging.js (ES module):
- `export const PAGE_SIZE = 100`
- `export function normPaging(p)` returns `{limit: number, has_more: boolean, next_cursor: string|null}`. has_more is true only when `p.has_more === true` and `next_cursor` is a non-empty string; next_cursor is null otherwise.
- `export function pagedPath(base, cursor)` returns `${base}?limit=100` plus `&cursor=${encodeURIComponent(cursor)}` when a cursor is given.

Store contracts (both modules namespaced, existing getters and mutations kept):
- state gains `paging: {limit: 100, has_more: false, next_cursor: null}`; getter `getPaging(state)`; mutation `savePaging(state, paging)`.
- `fetchAuditlog` / `fetchBuildLog`: GET `pagedPath(base, null)`. On success, commit items as today (buildlog through `normalizeBuildItems`) plus `savePaging(normPaging(result.paging))`. Return `state.items` (unchanged contract; may reject on a network failure as today).
- `fetchAuditPage(ctx, {cursor})` / `fetchBuildPage(ctx, {cursor})`: GET `pagedPath(base, cursor)`. Resolve `{ok: true, items, paging}` (build items normalised), or `{ok: false}` on `!result.success` or a rejected request. They never mutate state and never throw.

UI-SPEC hooks (data-cy): `audit-paging`/`build-paging` (wrapper), `audit-load-more`/`build-load-more`, `audit-filter-hint`/`build-filter-hint`, `audit-load-more-error`/`build-load-more-error`, `audit-paging-status`/`build-paging-status`.
