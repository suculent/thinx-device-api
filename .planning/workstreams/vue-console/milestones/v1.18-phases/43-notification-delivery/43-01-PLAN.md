<objective>
NOTIF-02: let several Legacy console tabs of one owner hold sockets on the same `/<owner>` path. Replace the path-keyed
duplicate-upgrade guard in `thinx-core.js` with per-connection tracking in a small module, `lib/thinx/socket_upgrade.js`,
that counts live sockets per verified owner, releases each socket on its own raw `close` (REFACTOR-03), and refuses
upgrades beyond 10 sockets per owner (D-05, D-07). Delivery stays with the messenger's per-owner Set (D-06), so
two tabs both receive owner frames and other owners receive nothing (D-08).

ZZ-* specs that exercise thinx-core never run (docker-entrypoint.sh deletes them before the CI run, and locally they
need Redis, CouchDB and /mnt/data/conf/config.json), so the upgrade logic moves into a module that a local spec drives
end to end with a real ws server, the real SocketSession and the real Messenger.
Output: `lib/thinx/socket_upgrade.js`, the thinx-core wiring, `spec/jasmine/SocketUpgradeSpec.js`,
`scripts/check-ws-multitab.js` (the live probe 43-03 runs against production), updated ZZ specs and a runbook note.
</objective>
