## Interface contract (used by 47-02 and 47-03)

- `utils/buildLog.js` `buildLogSearch(text, term, limit = 1000)` returns `{ segments, count, capped }`. `segments` is an
  ordered array whose `text` values concatenate to exactly `text`; a plain segment is `{ text, match: false }`, a match
  segment is `{ text, match: true, index }` with `index` 0..count-1 in document order (planner's discretion: the index
  lets the template mark the current match without counting). Non-string or empty `text` gives
  `{ segments: [], count: 0, capped: false }`; a non-string term, a term under 3 characters, or a blank term gives
  `{ segments: [{ text, match: false }], count: 0, capped: false }`.
- `BuildLogDialog.open(build)` returns a promise. It refuses (resolved promise, no state change, no dispatch, no
  `modal.show`) unless `build && typeof build.build_id === 'string' && build.build_id !== ''`.
- Dialog `data-cy` hooks: `build-log-search-bar`, `build-log-search`, `build-log-search-count`, `build-log-prev`,
  `build-log-next`, `full-build-log`, `build-log-match`, `build-log-error`, `build-log-retry`, `build-log-empty`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API -> browser (GET /logs/build/<id>) | build-log text is produced by firmware builds (repository content, compiler output) and is untrusted for rendering |
| user -> dialog (search term) | the typed term becomes a regular expression and drives DOM size |
| list row -> dialog (build object) | the build id chosen by a list decides which log is requested |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-47-01 | Tampering | log text rendered with highlights (stored XSS through build output) | high | mitigate | segments rendered only through text interpolation inside `mark`/`span`; grep gates on the raw-HTML directive and DOM HTML property in the dialog; D4 renders a log holding markup and asserts text nodes only, no `domProps.innerHTML` and no element vnode from the log |
| T-47-02 | Denial of service | multi-MB logs with very many matches (browser freeze) | medium | mitigate | 3-character minimum and 200 ms debounce; scan stops at the 1001st match; at most 1000 `mark` elements; non-matching text stays one interpolation; S4 and the E3 overflow backstop |
| T-47-03 | Denial of service | search term compiled into a RegExp (catastrophic backtracking) | medium | mitigate | every metacharacter is escaped, so the pattern is a literal string scanned linearly; no user regex (D-02); S2 checks literal matching; the empty-match guard prevents an infinite loop |
| T-47-04 | Information disclosure | search term and log text (logs can hold environment values) | low | mitigate | search is local to the dialog: no request, no store, storage or URL write and no console logging (grep gate on console calls in the dialog); the term resets on every open |
