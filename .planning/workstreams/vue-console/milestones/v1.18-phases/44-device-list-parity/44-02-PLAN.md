Grounded facts (verified by the planner on 2026-10-13):
- `src/core/api.js` `request()` catches JSON parse errors but not a rejected `fetch` (network failure), so
  `devices/buildFirmware` can reject; the in-flight guard needs try/catch/finally.
- BuildLogDialog's `open(build)` takes `{ build_id }` (DeviceDetail.vue calls it through `this.$refs.buildLogDialog.open(build)`)
  and `buildlog/fetchBuildDetail` encodes the id into `/logs/build/<id>`.
- Fonts: `_flaticon.scss` lives in `src/fonts/flaticon/` but writes `url('../fonts/flaticon/Flaticon.woff')`, because sass
  inlines partials and css-loader resolves `url()` against the entry, `src/styles/theme.scss`. The icomoon partial must do
  the same (`url('../fonts/icomoon/icomoon.woff')`); the UI-SPEC's file-relative `url('icomoon.woff')` would fail the
  webpack build. Legacy sources: `services/console/src/assets/thinx/fonts/icomoon.woff` (1308 bytes) and `icomoon.ttf`
  (1232 bytes). vue-cli inlines fonts under 8 KB as `data:font/…` URIs, which the Vue CSP `default-src … data:` allows.
- Dart Sass in compressed mode writes `content: "\e900"` as the literal U+E900 character (with a BOM at the start of the
  output), so the unit check must accept either the escape or the character.
- bootstrap-vue's `b-button` is functional; with `inheritAttrs: false`, `class` and `style` given to `<IconButton>` still
  land on its root wrapper span, so `class="ml-auto"` on the grid Edit button right-aligns it inside a flex row.
- Quick 261012-r9z: Codacy flags control-character regexes (`no-control-regex`); strip control characters with a
  `charCodeAt` scan (code below 32 or 127), not a regex.
- `perf:spotter` on the cfff199 build: JS 7.01 MiB raw / 2.76 MiB gzip, largest initial chunk 751.82 KiB gzip of an
  850000-byte budget; the console repo's CircleCI runs it through `yarn build:perf`.
