<objective>
Close the one Phase 46 verification gap: on Device Detail a save on one card must never silently discard an unsaved
change on another card. Today `loadDevice()` copies the stored device into every `editForm` field after each save, so
saving the alias, the description or the environment drops unsaved transformer ticks (and with them the
`Unsaved changes` note and the leave guard), and saving transformers drops unsaved alias and description text
(46-REVIEW CR-01). WR-05 has the same root cause: when the device re-read after a successful transformer save answers
`success: false`, the non-throwing `devices/fetchItems` leaves the stale list in the store and the card shows the old
ticks under `Transformers saved.`. Both are fixed in the `<script>` of `DeviceDetail.vue`, proven by unit checks that
run the page's real `loadDevice`, recorded in the review disposition and shipped through `thinx-staging` with the
46-05 ship pattern. Implements the D-09, D-10 and D-11 guarantees on every save path of the page.

Purpose: the phase goal says "no user change is silently lost"; POL-03's dirty state must survive a cross-card save.
Output: signed console commits (RED test, GREEN fix), one signed parent docs commit (review disposition), the signed
gitlink bump, both pushed to `thinx-staging`, the pipeline proof, live proofs and the operator UAT items.

Requirement status: this plan does not edit REQUIREMENTS.md by hand. POL-03 is marked Complete by the executor's
standard `update_requirements` step only once this plan's SUMMARY exists, and the SUMMARY is written only after the
ship and the live proofs pass, so POL-03 flips only after the gap closure ships. TRANS-03, TRANS-04, ENV-01 and
FIX-03 stay `Gaps Found` until the Phase 46 re-verification restores them.

Explicitly outside this plan (deferred, open in 46-REVIEW-DISPOSITION.md): WR-01 (`apienv.create` reports success
before Redis acknowledges the write; operator decision requested in 46-VERIFICATION), WR-02 (env store refresh through
the non-throwing loader), WR-03 (Edit and Add trim values; operator decision), WR-04 (`apienv.revoke` iterates a string
`names`), IN-01 (leave prompt after a successful revoke or transfer), IN-02 (name duplicate and trim handling across
pages), IN-03 (delete dialog usage count can be stale), IN-04 (editing a variable deleted elsewhere re-creates it).
