### WR-01: A previous account's profile survives sign-out and decides the admin guard and Sidebar for the next account

**Files modified (console submodule, paths relative to `services/console/`):**
`vue/src/store/auth.js`, `vue/src/pages/Login/Login.vue`, `vue/src/pages/OAuthReturn/OAuthReturn.vue`,
`vue/src/Routes.js` (comment only), `vue/tests/unit/audit-gaps-v118.cjs`, `vue/tests/unit/close-out-v118.cjs`
**Commit:** `9cb9ba2` (`9cb9ba2347c66f968c5ff939cf8002be92b9053e`, `git log -1 --format=%G?` = `G`)
`fix(vue): reset the profile on sign-out and before the sign-in read (48.1-REVIEW WR-01)`
**Applied fix:** followed the review's recommendation exactly.
- `auth/logout` now destructures `commit` and, after `await dispatch('clearSession')`, commits
  `profile/saveProfile` with `{}` at the root (`{ root: true }`). The reset is deliberately NOT in
  `clearSession`: `scheduleExpiry.expire` calls `clearSession` and then silently re-hydrates the same
  account, and the Header does not refetch, so wiping there would blank the Sidebar admin menu for the
  rest of the session. A comment in `auth.js` records this.
- `Login.login()` and `OAuthReturn.complete()` commit `profile/saveProfile {}` via `this.$store.commit`
  immediately before the `try { await this.fetchProfile() }`, so a failed read leaves `{}` (the guard then
  fetches and fails closed) rather than the previous account's `admin: true`.
- `Routes.js`: the `isAdminSession` comment now states what the "decide from the store without a
  request" shortcut relies on (logout + sign-in pages reset the profile).
- `audit-gaps-v118.cjs`: two new G-checks. **G7** evaluates the real `store/auth.js` (imports stubbed)
  against a mini root store seeded with `{ admin: true }`: `clearSession` alone keeps the profile (pins
  the "not in clearSession" constraint), `auth/logout` issues one `GET /logout`, drops the tokens/user
  and leaves exactly one root commit `profile/saveProfile {}`; the guard harness seeded with that store
  then dispatches `profile/fetchProfile` and redirects the non-admin second account to `/app/dashboard`.
  **G8** drives the real `Login.login()` and `OAuthReturn.complete()` with a stale admin profile and a
  rejecting `fetchProfile`: both commit `profile/saveProfile {}` once, the read observes `{}` (ordering),
  `setUser` receives `{}`, and the guard fetches and fails closed. K2/K3 were updated to expect the extra
  `profile/saveProfile` commit (K3's vm now carries a `$store.commit` recorder).
- `close-out-v118.cjs` H2 (pre-existing pin of `auth/logout`) now passes a `commit` recorder in the action
  context and asserts the single root reset; without it the action would have thrown `commit is not a
  function`.
