### WR-01 (iteration 3): The Header keeps showing the admin's name and avatar for the whole impersonated session; the fix's claim that Header and banner agree does not hold

**Files modified (console submodule, paths relative to `services/console/`):**
`vue/src/components/Header/Header.vue`, `vue/tests/unit/audit-gaps-v118.cjs`, `vue/tests/unit/close-out-v118.cjs`
**Commit:** `ec63c74` (`ec63c742e8b12f129370ae17b9bed4e0564a9de9`, `git -C services/console log -1 --format=%G?` = `G`)
`fix(vue): bind the header name and avatar to the profile store (48.1-REVIEW WR-01)`
**Applied fix:** followed the review's proposed fix. Two adaptations beyond it: `close-out-v118.cjs` also had to
change (two checks rendered the Header by assigning the former `profile` data field, which on a computed
produces the Vue "assigned to but it has no setter" warning that M1 asserts against), and the G9 Header check
drives a `Vue.observable` store stand-in rather than a plain object, because a Vue computed caches until a
reactive dependency changes (Vuex state is reactive, so this models the real store).
- `Header.vue`: `profile` is now a computed, `return this.getProfile() || {};`, over the `profile/getProfile`
  binding that `mapGetters` already placed in `methods`; the `data()` field is gone (`data()` stays and returns
  `{}` because the harness's `pageVm` calls `def.data()`). `mounted()` keeps exactly one `fetchProfile()` with
  the catch that absorbs a rejected read, and no longer copies the result; `avatarFallback` and the template
  are unchanged and read `this.profile`, so the avatar follows the store too. The deep-link spec's per-load
  profile read count (guard + Header) is unchanged. The reset-then-read in `confirmImpersonate` now shows as a
  blank name for the duration of the read, then the impersonated user's name, under the still-mounted Layout.
- `audit-gaps-v118.cjs` **K1** asserts `profile` is a computed and not a data field, one profile read per
  mount, the rejected read leaving the store stand-in (and so the computed) at `{}` while the build log is
  still fetched, the working read filling the computed through the store, and the undefined-getter fallback.
  **G9** gains a final block: one `Vue.observable({ profile })` stand-in is shared by a rendered Header
  (`renderPage` + the real `mounted()`), the real `confirmImpersonate()` and the real `exit()`; the rendered
  `.text-white` span reads `Ada Admin`, then `Impersonated User` after `confirmImpersonate()` (the read is
  asserted to follow the reset), then blank after `exit()`, with the Header's own `fetchProfile` called
  exactly once throughout (no second `mounted()`), no render error and no Vue warning. The file header and the
  G9 lead-in comment mention the Header. IMPERSONATED() gained `first_name`/`last_name`.
- `close-out-v118.cjs` **I8** and **M1** render the Header with `getProfile: () => ...` in place of the
  former `profile:` state; the I8 comment no longer cites a line number.
- Red check: with the committed harness and the previous `Header.vue` restored, K1 fails on
  `profile is a computed` and G9 fails on `Header: shows the impersonated user without a remount`; with the
  new Header both pass.
