Grounded facts (verified by the planner on 2026-10-13):
- `src/core/api.js`: `request(method, path, body)` sends GET with plain `fetch` and every other method through
  `fetchWithCsrf(this.csrfBase(), this.composePath(path), options)` (:100-102); there is no `$patch` (:132-146).
  `parseResult` returns a `success: false` body unchanged, so `{success: false, response: 'invalid_key_name', reason}`
  reaches the page with `reason` intact; a body-less reply becomes `{success: false, status, response: null}`.
- `src/utils/cookies.js` `fetchWithCsrf(apiBase, url, init)` (:104-112) adds `X-XSRF-TOKEN` from
  `ensureCsrfToken(apiBase)` whatever the method and retries once after a `csrf_token_invalid` 403; it reads
  `document.cookie` and calls global `fetch`. It ends with `export default { … }`.
- `src/store/rsakeys.js` actions `fetchItems` (throws on failure), `createItem(name)` (`$put('/rsakey')`, refreshes on
  success), `deleteItems(filenames)`; the store has no rename action.
- The API contract from 45-01 (Contract section of 45-01-PLAN.md): PATCH /api/v2/rsakey `{filename, name}`; 400
  `{success:false, response:'invalid_key_name', reason}` with reasons `empty`, `too_long`, `control_chars`,
  `line_separator`, `bidi`; 404 `key_not_found`; 500 `rename_failed`; 200 `{success:true, response:<list entry>}`.
  The create routes give the same 400 shape. The validator scans every UTF-16 code unit of the untrimmed string first
  (code below 0x20, 0x7F, 0x80..0x9F: control_chars; 0x2028/0x2029: line_separator; 0x202A..0x202E, 0x2066..0x2069,
  0x200E, 0x200F: bidi; the first offending unit decides), then empty after trim, then trimmed length above 120:
  too_long. A non-string is `empty`.
- Shared test cases (identical to the server's): ok `Firmware 🚀`, `Ünïcödé`, `مفتاح`, `Firmware Repository`, 120 × `x`;
  empty `''`, `'   '`, `{}`, `[]`, `42`, `null`, `undefined`; too_long 121 × `x`; control_chars TAB alone, `a` TAB `b`,
  `a` DEL `b`, `a` U+0085 `b`, `Firmware` plus a trailing LF; line_separator `a` U+2028 `b`, `a` U+2029 `b`, U+2028 alone;
  bidi `a` U+202E `b`, `a` U+202A `b`, `a` U+2066 `b`, `a` U+2069 `b`, `a` U+200E `b`, `a` U+200F `b`.
- `tests/unit/milestone-v116.cjs` loads Rsakeys.vue at :70 with `load(file, extra)` (imports stripped, names in
  `extra` in scope) and drives `create` at :310-312, so once `create` calls `validateKeyName` the load needs the real
  functions; it loads plain ES modules as at :43-44 (`utils/buildLog.js`, `export function` rewritten to
  `module.exports.<name> =`).
- `tests/unit/device-list-parity.cjs` `loadModule` (:60-65) handles `export const|let|function` but not a trailing
  `export default {…}`; strip that line when loading cookies.js.
- Quick 261012-r9z: Codacy flags control-character regexes; compare code units numerically and keep backslash escape
  sequences for control, separator and bidi characters out of `keyNames.js`.
