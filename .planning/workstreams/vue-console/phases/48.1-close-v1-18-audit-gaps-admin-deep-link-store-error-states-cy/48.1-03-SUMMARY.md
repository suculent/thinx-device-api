### Scope-boundary discovery (not auto-fixed, logged)

**1. [Scope boundary - pre-existing defect outside the plan's files] Build-log step does not scroll the modal log box; the plan's `scrollTop > 0` assertion is withheld**
- **Found during:** Task 3 (`build-log-search.spec.js` test 1 failed on the first run: `expected 0 to be above 0`)
- **Issue:** `BuildLogDialog.step()` sets `current` and queues `scrollToCurrent()` with `this.$nextTick`. The `<pre ref="log">` is inside a non-static `b-modal`; bootstrap-vue 2.21.2's `BVTransporter` pushes the new slot vnodes to its target from its `updated()` hook, and Vue 2 calls `updated()` hooks after `resetSchedulerState()`, so the target's re-render is queued as a new tick, after the dialog's callback. `scrollToCurrent` therefore finds the previous current mark. Measured with two throwaway probe specs (deleted, never committed; the second wrapped `Element.prototype.scrollTop`): `scrollHeight` 2372, `clientHeight` 526, current mark `offsetTop` 1169, `scrollTop` 0, and the only app-side write was `-198.5` (= first mark's offsetTop 57 minus half the box). The highlight moves, the view does not. The element is scrollable (a manual `scrollTop = 900` read back 900).
- **Why not fixed here:** the fix is in `vue/src/components/BuildLogDialog/BuildLogDialog.vue`; the plan's flagged prohibition forbids any `vue/src` change in this test-only plan, and the executor scope boundary says pre-existing defects not caused by the task are logged, not fixed.
- **What was done:** the spec asserts that the current mark moves (`eq(1)` has `build-log-match--current` and `aria-current="true"`, the first does not) and carries a comment naming the withheld assertion; `deferred-items.md` (status open) records the evidence and a candidate one-file fix; a WINDOWS ledger entry (`unmet-truth`) was appended; the coverage block carries it as D6 with `human_judgment: true`.
- **Files modified:** services/console/vue/cypress/integration/build-log-search.spec.js, .planning/.../deferred-items.md
- **Committed in:** 4fef60d (spec), parent docs commit (deferred items)

**2. [Rule 1 - Bug in the new test file] Y1 flagged the word `retries` in a spec comment**
- **Found during:** Task 3 unit run (`FAIL Y1 build-log-search.spec.js ... has no retries`)
- **Fix:** the comment was reworded; the hygiene regex is correct as data and stays untouched.
