# Phase 47 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Vue console only (`services/console/vue`, a git submodule):
- `src/components/BuildLogDialog/BuildLogDialog.vue`: search bar, highlights, stepping (BUILD-03), id-only `open()` and the loading reset (D-15, 35 IN-07), and the error and empty states of the dialog;
- `src/utils/buildLog.js`: a new pure search helper next to `buildLogText()` and `buildStatusVariant()`;
- `src/pages/Visits/Visits.vue`: the dashboard Recent Builds card gets View + Download in one actions cell and a `BuildLogDialog` (POL-02, D-13);
- `src/components/Notifications/Notifications.vue`: navbar Recent Builds rows without a `build_id` are static, and the list markup is fixed (D-14, 35 IN-06);
- `src/pages/History/History.vue` and `src/pages/Devices/DeviceDetail.vue`: consistency only (UI-B14);
- tests: `tests/unit/` (WR-01, IN-01, the status mapping lock, the search helper) and `cypress/integration/device-detail.spec.js` (WR-01 e2e, IN-03).

**Mode.** Autonomous, no user questions. D-01..D-18 in `47-CONTEXT.md` are locked. The visual system, `IconButton`, the colour measurements, the 4/8/16/32 spacing and the copy rules are inherited from the approved Phase 44, 45 and 46 contracts (`46-UI-SPEC.md`), including "no `text-muted` on content" for every element this phase touches. Every choice made here is recorded as a `UI-Bnn` decision. The `B` prefix does not collide with Phase 44 `UI-Dnn`, 45 `UI-Knn` or 46 `UI-Tnn`.

**Already landed (console `38eb95b`).** `buildStatusVariant()` is used by History, DeviceDetail, Visits and Notifications, and History and DeviceDetail hide View without a `build_id`. This phase verifies the mapping and locks it with a test (UI-B10). It does not rebuild it.

**Out of scope.** These stay as they are:
- the full-log payload size (AR-36-01, deferred) and any parent API change;
- the Legacy console (`services/console/src`);
- a regex or case-sensitive search toggle (D-02, deferred);
- the History page's own `Search build log...` list filter, the History inline log preview and Expand;
- the dashboard Audit card, metric cards and page `Loading...`;
- the dashboard's dependence on the store that the navbar fills (the card shows `No builds yet.` until the navbar has fetched; pre-existing);
- the theme-wide contrast of `$link-color` on dark surfaces, `.btn-primary`, `.badge-info` and `.alert-danger` (routed to Phase 48, see the Color section);
- repairing the Cypress suite (Phase 48 CI-07).

Declared values for anything this phase adds or changes (all multiples of 4):

| Token | Value | Usage in this phase |

| 3xl | 64px | not used |

Width limits (multiples of 8): the search field is `flex: 1 1 200px; max-width: 320px`; the count is `min-width: 88px` so the step buttons do not move as `3 / 17` turns into `No matches`.

Exceptions (inherited, not touched): modal header, body and footer padding (`1rem` = 14px); table cell padding (`.table-sm` `.3rem`); the navbar row's `notificationIcon` `margin-right: 1rem` and the list's `320px` height; the View link button's `p-0` (no padding, by design: it reads as a link inside the cell). The `mark` element gets `padding: 0` (Bootstrap reboot sets `.2em`, which would shift log columns).

## Build Log Dialog — Layout & Interaction Contract (BUILD-03, D-01..D-12, D-15)

Dialog order, top to bottom:
1. modal header `Build Log — {build_id}` with ✕ (unchanged);
2. **only when log text is shown:** the search bar (UI-B01);
3. one of: loading line, error alert, log box, empty line (exactly one renders);
4. footer `Close` (unchanged).

```
┌ Build Log — 3f9a… ───────────────────────────────── × ┐
│ [🔍 Search log (3+ characters)]  3 / 17  [<] [>]      │  ← sticky, 8px gaps
│ ┌───────────────────────────────────────────────────┐ │
│ │ ... log ... ▮match▮ ... ██current██ ...           │ │  ← 70vh, scrolls itself
│ └───────────────────────────────────────────────────┘ │
│                                              [Close]  │
└───────────────────────────────────────────────────────┘
```

| ID | Decision | Source |
|----|----------|--------|
| UI-B01 | Search bar markup: `<div v-if="text && !loading && !error" class="build-log-search" role="search" aria-label="Search this build log" data-cy="build-log-search-bar">` holding, in this order: <ol><li>`<b-input-group class="build-log-search__field">` with `<b-input-group-prepend is-text><i class="fa fa-search" aria-hidden="true"></i></b-input-group-prepend>` and `<b-form-input ref="searchInput" v-model="searchInput" type="text" aria-label="Search this build log" placeholder="Search log (3+ characters)" autocomplete="off" spellcheck="false" data-cy="build-log-search" @keydown.enter.prevent="onSearchEnter" />` (`type="text"`, not `search`, so Esc is never eaten by a native clear);</li><li>the count (UI-B05);</li><li>`<IconButton icon="fa fa-chevron-left" label="Previous match" :disabled="!count" data-cy="build-log-prev" @click="step(-1)" />`;</li><li>`<IconButton icon="fa fa-chevron-right" label="Next match" :disabled="!count" data-cy="build-log-next" @click="step(1)" />`.</li></ol>CSS: `.build-log-search { display: flex; flex-wrap: wrap; align-items: center; gap: 8px; padding-bottom: 8px; position: sticky; top: 0; z-index: 1; background-color: $modal-content-bg; }`, `.build-log-search__field { flex: 1 1 200px; max-width: 320px; width: auto; }`. The `IconButton`s keep their Phase 44 behaviour: glyph only below 992px, glyph + `Previous match` / `Next match` from 992px; the label is also the `aria-label` and the hover tip. Inside the bar, `.build-log-search .icon-button { margin-right: 0; }` removes the inherited 4px right margin, so the flex `gap` alone spaces every block (field, count, `<`, `>`) exactly 8px apart | D-09, D-11, Phase 44 UI-D06..D08 |
| UI-B02 | Live search (D-01, D-07): `searchInput` updates on every keystroke; a 200 ms debounce copies it to `term`. The search runs when `term.length >= 3` and `term.trim() !== ''`; the term is used as typed (spaces count, no trim). A shorter or blank term means no search: no `<mark>`, empty count, step buttons disabled. When `term` or `text` changes, the current match resets to the first match from the top and is scrolled into view (UI-B06). The debounce timer is cleared in `@hidden` and `beforeDestroy` | D-01, D-07 |
| UI-B03 | Pure helper in `utils/buildLog.js`: `buildLogSearch(text, term, limit = 1000)` returns `{ segments, count, capped }`. `segments` is an ordered array of `{ text, match }` whose texts concatenate back to exactly `text`. Matching is plain text and case-insensitive: `new RegExp(escapeRegExp(term), 'gi')`, where `escapeRegExp` escapes ``\ ^ $ . * + ? ( ) [ ] { } \|`` and `/`, scanned left to right with non-overlapping matches. A regex is used instead of `toLowerCase()` + `indexOf` so indices always stay aligned with the original text (some characters change length when lower-cased). The scan stops after `limit + 1` matches: `count = min(found, limit)`, `capped = found > limit`, and only the first `limit` matches become `match: true` segments; the rest of the text is one plain segment. A term under 3 characters or blank returns `{ segments: [{ text, match: false }], count: 0, capped: false }`. An empty `text` returns `{ segments: [], count: 0, capped: false }` | D-02, D-05, D-06 |
| UI-B04 | Rendering (D-05): `<pre ref="log" class="build-log-text" data-cy="full-build-log">`. When `count === 0` it holds `{{ text }}` exactly as today. Otherwise it renders the segments with `v-for`: a match is `<mark class="build-log-match" :class="{ 'build-log-match--current': n === current }" :aria-current="n === current ? 'true' : null" data-cy="build-log-match">{{ seg.text }}</mark>` and a plain segment is `<span>{{ seg.text }}</span>`. Every segment is `{{ }}` interpolation: no `v-html`, `innerHTML`, `domProps` or `$el.insertAdjacentHTML` anywhere in the dialog, so a log line like `<img src=x onerror=alert(1)>` renders as those characters. The `<pre>` element, its `v-for` children and their closing tags are written **on one template line with no whitespace between them**: whitespace inside `<pre>` is preserved by the Vue compiler and would otherwise add blank lines to the log | D-05, BUILD-03 SC 1 |
| UI-B05 | Count (D-10): `<span class="build-log-search__count" data-cy="build-log-search-count">` holds a visible `aria-hidden="true"` text and a screen-reader live text: `<span aria-hidden="true">{{ countText }}</span><span class="sr-only" aria-live="polite" aria-atomic="true">{{ countSpeech }}</span>`. Visible: `3 / 17`; `3 / 1000+` when capped; `No matches` when a valid term finds nothing; empty when there is no valid term. Spoken: `Match 3 of 17`; `Match 3 of more than 1000`; `No matches`; empty. CSS: `.build-log-search__count { min-width: 88px; white-space: nowrap; font-size: .875rem; font-weight: 400; font-variant-numeric: tabular-nums; }` | D-06, D-10 |
| UI-B06 | Stepping (D-03, D-04): `step(1)` / `step(-1)` move `current` and wrap (`(current + d + count) % count`). Enter in the field calls `step(1)`, Shift+Enter `step(-1)`. If the debounce is still pending, Enter applies the term at once (selecting the first match) instead of stepping. Esc is not handled by the field: it bubbles to the modal, which closes (bootstrap-vue default). After each change of `current`, on `$nextTick`, the current `<mark>` is centred vertically inside the log box by setting the `<pre>`'s own `scrollTop` (`.build-log-text { position: relative; }`, `scrollTop = mark.offsetTop - (pre.clientHeight - mark.offsetHeight) / 2`, clamped by the browser). Only the `<pre>` scrolls: the modal, the page and the focus stay where they are, so focus never leaves the field during Enter stepping. Scrolling is instant (no smooth behaviour), which also respects reduced motion | D-03, D-04 |
| UI-B07 | Log box CSS in `_build-log.scss`: `.build-log-text { position: relative; max-height: 70vh; overflow: auto; margin: 0; padding: 16px; white-space: pre-wrap; overflow-wrap: anywhere; line-height: 1.5; background: $build-log-bg; color: $build-log-color; }`. `.build-log-text .build-log-match { padding: 0; border-radius: 0; font: inherit; background-color: $build-log-match-bg; color: $build-log-match-color; }`. `.build-log-text .build-log-match--current { background-color: $build-log-current-bg; color: $build-log-current-color; }` | D-08 |
| UI-B08 | Dialog lifecycle (D-11, D-12, D-15, 35 IN-07): <ul><li>`open(build)` uses only `build.build_id`. When it is empty (missing, `''` or not a string), `open()` returns `Promise.resolve()` without showing the modal, without touching state and without dispatching `buildlog/fetchBuildDetail`. There is no fallback to `build.id`.</li><li>A valid `open()` resets `searchInput`, `term` and `current` to empty / 0, then clears `text` and `error`, shows the modal and loads.</li><li>`Try again` calls `load()` and keeps the term: when the text arrives the search re-runs and selects the first match.</li><li>`@hidden="onHidden"`: `requestId++`, `loading = false`, and the debounce timer is cleared.</li></ul> | D-11, D-12, D-15 |
| UI-B09 | Dialog states (36-UI-REVIEW Pillar 1/6, 46 text rules): <ul><li>Loading (unchanged): `<div role="status"><b-spinner small /> Loading build log…</div>`.</li><li>Error: `<b-alert variant="danger" show data-cy="build-log-error">Could not load this build log. <b-button size="sm" variant="default" data-cy="build-log-retry" @click="load"><i class="fa fa-refresh" aria-hidden="true"></i><span class="button-text">Try again</span></b-button></b-alert>`. The message string stays `Could not load this build log.` (asserted by `milestone-v116.cjs:286`).</li><li>Empty: `<p class="mb-0" data-cy="build-log-empty">No log output is available for this build yet.</p>` in body colour (`text-muted` removed).</li><li>The title keeps `'Build Log — ' + buildId`; it can no longer be blank, because `open()` refuses an empty id.</li></ul> | 36-UI-REVIEW, D-15 |

### Focal point

In the dialog, the eye lands on the log box; the search bar above it is quiet (neutral `#474D84` buttons, body-colour count) until there is a match. Then the single bright amber current match is the strongest element in the dialog, the softer amber matches show where the others are, and `3 / 17` next to the field says where you are. On the dashboard card, each row reads time → device → status badge → View (link) → Download (blue button): Download stays the card's one filled call to action, and View sits before it as a quieter link, the same as on History and Device Build History.

Open accessibility notes (outside the closed taxonomy, accepted):
- Focus is not moved into the search field when the log arrives; bootstrap-vue focuses the modal as today, and Tab reaches the field after the header ✕. Moving focus after an async load would surprise screen-reader users.
- `<mark>` is announced as highlighted text by some screen readers; the current one also carries `aria-current="true"`. The live count speaks `Match 3 of 17` instead of reading `3 / 17` as a fraction.
- Enter stepping keeps focus in the field, so a keyboard user can step through every match without leaving it, and Esc still closes the dialog.
- The navbar's static rows are announced as plain text, not as disabled buttons, because they offer no action.
