<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (console origin) -> API PUT/DELETE /api/v2/env, POST /api/user/env/* | untrusted JSON `key`, `value`, `names` under a cookie session or Bearer token |
| API -> Redis `env:<owner>` | the whole variable array is rewritten on every add or overwrite |
| Redis -> firmware builds | builder.js reads the owner's variables into every build |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-46-01 | Tampering | apienv.create name matching (an edit deletes neighbouring variables) | high | mitigate | exact `String(key)` equality with the stored property name; L1..L5 and R1 assert every neighbour survives with its value |
| T-46-02 | Information disclosure | env values in responses, logs and test output | medium | mitigate | no log line added; list routes stay names-only and R3 asserts no stored value appears in their body; synthetic values only in the spec |
| T-46-03 | Spoofing | cross-site env writes (CSRF) | high | mitigate | routes unchanged; R1 asserts `verifyCsrfToken` is the first handler on all four mutating routes; CsrfRouteInventorySpec rerun |
| T-46-04 | Elevation of privilege | writing another owner's variables | high | mitigate | owner only from `sanitka.owner(req.session.owner)` (unchanged); L4 asserts the other owner's stored string is byte-identical; R4 asserts no write without a session |
| T-46-05 | Tampering | Legacy console compatibility | medium | mitigate | R1..R3 compare raw envelope text for v2 and Legacy routes |
| T-46-06 | Repudiation | a failed Redis write is still answered `success: true` (pre-existing, `redis.set` has no callback) | medium | accept | out of D-02's scope (operator limited the parent change to exact matching); the write stays a single `set`, so a failure never leaves a partial array; recorded in the SUMMARY as a follow-up candidate |
| T-46-SC | Tampering | npm/pip/cargo installs | low | mitigate | no install, upgrade or lock-file change in this plan |
</threat_model>
