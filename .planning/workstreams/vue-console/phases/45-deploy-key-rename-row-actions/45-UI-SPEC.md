# Phase 45 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Vue console only: the Deploy Keys page `services/console/vue/src/pages/Rsakeys/Rsakeys.vue` and its store
`src/store/rsakeys.js` (KEY-04 rename UI, KEY-05 row actions, KEY-06 column widths, POL-04, and the console side of
FIX-04). The parent API work (D-01..D-08, D-13..D-16) has no visual surface beyond the fingerprint string and the
`reason` codes this page displays. No Legacy (`services/console/src`) change (D-16, out of scope).

**Mode.** Autonomous, no user questions. D-01..D-16 in `45-CONTEXT.md` are locked. The visual system, `IconButton`, the
colours, the 4px action gap and the copy rules come from the approved Phase 44 contract (`44-UI-SPEC.md`, UI-D06..UI-D08,
UI-D16) and its fixes (`44-REVIEW-FIX.md`: load-error copy pattern, no `text-muted` on content, no Bootstrap 5 `gap-N`).
The Phase 38 UI review (`.planning/milestones/v1.16-phases/38-deploy-key-management/38-UI-REVIEW.md`) supplies the
problems this page must fix. Each choice made here is recorded as a `UI-Knn` decision (prefix `K` so it never collides
with the Phase 44 `UI-Dnn` ids referenced below).

**Out of scope.** The `Loading…` text that replaces the table on every reload (38-UI-REVIEW minor, layout jump; kept as
is), a search box or select-all checkbox, any Legacy wording ("Revoke" stays in Legacy, "Delete" stays in Vue), the
created-key result modal (`rsakey-result-modal`, unchanged), and Cypress specs (Phase 48 CI-07).

### Integration prerequisites (found while scouting, not UI decisions)

- `lib/middleware/cors.js:22` has `ALLOWED_METHODS = "GET,PUT,POST,DELETE,OPTIONS"`. A cross-origin `PATCH /api/v2/rsakey`
  from the console fails its preflight unless `PATCH` is added there (and covered in `spec/jasmine/ZZ-CORSSpec.js`).
- `fetchWithCsrf` must send the XSRF header for `PATCH` like the other mutating verbs (D-02 CSRF).
- `parseResult` returns a `success: false` body as-is, so `{ success: false, response: "invalid_key_name", reason }`
  reaches the page with `reason` intact (D-07). The create response has no `fingerprint` field; the list does.

Open accessibility note (outside the closed taxonomy, accepted): the truncated name's full text is a native `title`, so
it appears on mouse hover only; keyboard users read the full name in the rename field and screen readers get the full
text because only the visual box is clipped. The eye button announces its state with `aria-expanded` and points at the
key text with `aria-controls`. The feedback lines use `aria-live="polite"` and are tied to their fields through
`aria-describedby`, so a rejected name is announced without moving focus.

  `key-fingerprint`, `key-show`, `key-copy`, `key-rename`, `key-delete`; the Actions `td` has `actions-cell`; Generated and
  Public key `td`s have `text-nowrap`; no visible `Select` header text; the Generate `b-form` contains no Delete button;
  `key-bulk-delete` exists outside it; no `text-muted` anywhere in the template.
- Show toggle: clicking `key-show` renders `[data-cy=key-text]` with the pubkey and flips the label to `Hide key` and
  `aria-expanded` to `true`; a second click removes it.
- Delete: cancelled confirm sends nothing; the row confirm options have `cancelTitle: 'Keep key'`, the bulk ones `Keep key`
  (one) / `Keep keys` (several), and no confirm uses `Cancel`; confirm text contains the key name; two rapid clicks open one confirm and send
  one request; while pending the row's four buttons are disabled and the trash label is `Deleting…`; a failure re-enables
  them and sets the row-delete error copy. Bulk: label `Delete selected` when nothing is selected, `Delete selected (2)`
  with two; same single-request guard.
- Rename: the modal footer buttons read `Keep current name` and `Save name` (no `Cancel` / `Save` text in the template);
  invalid client name sends no request and shows the sentence; unchanged name sends no request; a
