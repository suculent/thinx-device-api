<interfaces>
Phase-wide contract of lib/thinx/transit.js. Plans 40-02, 40-03 and 40-04 depend on these exact names and strings.

- module.exports is the class Transit. Statics: Transit.TransitError, Transit.REASONS, Transit.shared(), Transit.probeSoon(opts), Transit.unavailableSentence(reason).
- TransitError extends Error with fields reason (one of REASONS) and status (HTTP status number or null); its message is "transit_" + reason and nothing else.
- REASONS, the only words ever logged, alerted or put in a build log: not_configured, unreachable, tls, sealed, denied, bad_ciphertext, server_error.
  - not_configured: BAO_ADDR missing, unparsable or not https:, CA file unreadable, role_id or secret_id empty.
  - unreachable: ECONNREFUSED, ENOTFOUND, EAI_AGAIN, ECONNRESET, ETIMEDOUT, ABORT_ERR (timeout).
  - tls: any certificate or hostname verification error code (UNABLE_TO_VERIFY_LEAF_SIGNATURE, ERR_TLS_CERT_ALTNAME_INVALID, CERT_HAS_EXPIRED, DEPTH_ZERO_SELF_SIGNED_CERT, SELF_SIGNED_CERT_IN_CHAIN and the other ERR_TLS_ / CERT_ codes).
  - sealed: HTTP 503. denied: HTTP 403, and login HTTP 400. bad_ciphertext: decrypt HTTP 400. server_error: any other non-2xx, an unparsable body, a body over 64 KiB or a 2xx missing the expected field.
- new Transit(opts), every option optional: addr (default process.env.BAO_ADDR), caFile (default process.env.BAO_CACERT), readSecret (default secrets.js readSecret), now (default Date.now), requestTimeoutMs 3000, refreshMarginMs 120000, slackNotify (factory, default require("slack-notify")), webhook (default readSecret("SLACK_WEBHOOK")), hostname (default os.hostname()), log (default console.log).
- async encryptKey(buf) takes a Buffer and resolves the string "vault:vN:<base64>"; async decryptKey(ciphertext) resolves a Buffer the caller zeroes with fill(0); async probe() performs one login only and resolves true. All three reject only with TransitError.
- HTTP calls: POST /v1/auth/approle/login {role_id, secret_id} reading auth.client_token and auth.lease_duration; POST /v1/transit/encrypt/thinx-deploy-keys {plaintext: base64} reading data.ciphertext; POST /v1/transit/decrypt/thinx-deploy-keys {ciphertext} reading data.plaintext (base64). Token header x-vault-token. No AAD or context field and no other endpoint.
- Log line, the only one this module writes: "[transit] <op> failed: <reason> status=<n>" with op one of login, encrypt, decrypt, probe and n the HTTP status or 0. Plus "[transit] probe ok" on a good boot probe.
- Slack texts (D-05, Phase 39 style):
  - "THiNX OpenBao: API Transit FAILING on <host> since <ISO ts>: <REASON>. One alert per incident; recovery will be announced."
  - "THiNX OpenBao: API Transit RECOVERED on <host>; failing since <ISO ts> (<REASON>)."
  - REASON is the reason class in upper case.
- unavailableSentence(reason): unreachable "key service unreachable", sealed "key service sealed", denied "key service refused the request", tls "key service certificate not trusted", not_configured "key service not configured", bad_ciphertext "stored key could not be decrypted", anything else "key service error".
- Transit.shared() returns one lazily built instance per process. Transit.probeSoon({delayMs = 5000, env = process.env, transit}) returns null when env.ENVIRONMENT is "test" or env.BAO_ADDR is unset. Otherwise it returns an unref'd timer that calls probe() once, and every rejection is caught.
- CI and laptop throwaway values, labelled as such like thinx-ci-influx-token: role_id thinx-ci-bao-role, secret_id thinx-ci-bao-secret, dev root token thinx-ci-bao-root.
