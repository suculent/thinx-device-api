<objective>
Make every new deploy key Transit ciphertext and make keyed builds read both formats. A Transit key is decrypted into a per-attempt ssh-agent; a legacy passphrase key keeps today's path.

Purpose: KEYENC-01 (ciphertext only on disk), KEYENC-02 (in-memory key, agent, no passphrase or askpass), KEYENC-06 (dual read by file format) and the generation half of KEYENC-03 (no passphrase fallback). Also D-01 (skip an undecryptable Transit key and keep trying) and D-04 (one explicit build-log line, no new status). Milestone D-01 and D-04 are carried forward.
Output: lib/thinx/keyformat.js, the Transit generate() path, the agent fetch path and fetchDetailed in git.js, the builder log line, a shared fake Transit, and updated and new specs.

Out of scope here, and in Plan 40-03: the create() mapping to key_service_unavailable, the kill switch, the router 503 and the consoles. Commit locally only; push nothing.
</objective>

Created here and consumed by Plans 40-03 and 40-05:
- keyformat.detect(text) returns "transit", "legacy" or "unknown". Transit is the trimmed text matching ^vault:v[1-9][0-9]*:[A-Za-z0-9+/]+={0,2}$. Legacy is a first line matching ^-----BEGIN [A-Z0-9 ]*PRIVATE KEY-----$. Anything else, including non-strings, is unknown.
- keyformat.readKey(filePath) returns {kind, text, cause}:
  - kind is transit, legacy, unknown or unreadable;
  - text is the trimmed ciphertext for transit and null otherwise;
  - cause is null, not_regular, too_large (over keyformat.MAX_KEY_FILE_BYTES = 65536), unknown_key_format or read_error.
  - It opens with fs.openSync(path, "r"), following a symlink exactly as `ssh -i` already does for legacy keys, fstat-checks a regular file, and never includes file content or e.message in what it returns.

<assumption_delta_decision>
- Signal: the read path is chosen by file format, so a second stored key format now sits beside the passphrase PEM.
- Noun that is now primary: the deploy-key storage format, with Transit ciphertext `vault:vN:` as the primary representation.
- Decision: add-alongside. Transit is primary for every new key. Legacy PEM (passphrase-encrypted PKCS#8 since 2022-05-17, unencrypted ssh-keygen keys before) stays a read-only variant until the Phase 41 migration. Promoting now would break every legacy build at cut-over, which KEYENC-06 forbids.
- Accepted debt: two read paths in git.js (agent and askpass), and GIT_KEY_PASSPHRASE kept in the image, the env and the secrets.
- Promote trigger: the Phase 41 migration reports zero legacy keys (KEYMIG-01). KEYMIG-02 then deletes the legacy path, keyPassphrase(), the askpass helper and the passphrase.
- Invariant test (accepted, Task 3): every supported key format reaches its matching keyed-attempt path, and an unknown format reaches none (KeyFormatSpec).
</assumption_delta_decision>

## Flagged assumptions (spec-less probe, unresolved edges)

- KEYENC-01 (unclassified edge): assumes the ssh_keys GlusterFS volume honours the 'wx' exclusive create and mode 0600, as legacy keys already rely on. Also assumes the JS string generateKeyPair returns cannot be wiped; only the Buffer handed to Transit is zeroed. This is accepted: the plaintext never reaches disk.
- KEYENC-02 (concurrency edge, crash case): assumes the API process is the container's main process, so a crash stops the container and every agent with it. If an agent were ever orphaned, `-t 1260` bounds how long it holds the key. A leftover thinx-agent-* directory holds only a socket and a public key. The executor confirms the container's PID 1 in the 40-05 live check and records it.
