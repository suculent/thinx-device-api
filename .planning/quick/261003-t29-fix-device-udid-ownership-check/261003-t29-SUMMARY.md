# Quick 261003-t29: Device udid ownership check Summary

**The cross-owner udid IDOR (T-skk-09) is closed on every console/API device route. One shared check in `lib/thinx/device.js` (`Device.isOwnedBy`, `#fetchOwned`, `#filterOwned`) backs a `withOwnedDevice` gate in `lib/router.device.js` and the transfer request/accept/migrate path. Another owner's udid now gets the same HTTP 200 `no_such_device` answer as an unknown udid.**

## Response decision

Every refusal is HTTP 200 with the body `{"success":false,"response":"no_such_device"}`, sent through `Util.responder`. The same body answers a missing udid, a foreign udid, a malformed udid that passed the presence checks, and a CouchDB error. Reasons:

1. It is already the answer of the only owner-checked udid path. `device.run_transformers` answers `no_such_device` for both missing and foreign devices, and `ZZ-RouterTransformerSpec` pins that text.
2. The legacy API reports not-found as 200 with `success:false`. Both consoles branch on `success` inside their success handlers, and a 404 would send these calls into jQuery/axios error paths.
3. `ZZ-RouterBuilderSpec` "POST /api/v2/build (JWT, valid) V" attaches `envi.dynamic.udid`, which has no device, and asserts status 200.

The foreign and missing cases both make exactly one `devicelib.get`, so the work done does not reveal whether a device exists.

## Operator-facing behaviour changes

- A foreign or missing udid on any console/API device route answers 200 `{"success":false,"response":"no_such_device"}`.
- detail and envs on a missing udid now answer that JSON. Before, they answered the bare strings `detail_device_not_found` / `getenv_device_not_found`.
- Push and configuration publish only to the caller's own udids. Foreign and unknown udids are dropped, and a list with nothing owned answers `no_such_device`.
- A device edit ignores `owner` and `previous_owner`. Only a transfer changes ownership.
- Notification and data routes now work for a router-verified API-key caller's own devices. Before, they used `req.session.owner`, which is null for API-key callers.
- Transfer request:
  - It refuses with `no_such_device` when any udid is not the sender's.
  - It answers `missing_subject` when `udids` is not a non-empty array.
- POST transfer accept:
  - It ignores body udids that are outside the transfer, and refuses with `no_such_device` when none remain.
  - It skips a device whose originator no longer owns it.
- The GET e-mail link works as before for valid transfers.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The local messenger fake mirrors the real `missing_udids` answer**
- **Found during:** Task 1 (writing the RED spec)
- **Issue:** The plan's messenger fake `push()` always answered `(true, "pushing_configuration")`. The case "Session A with {} → exactly missing_udids" depends on `devices.push` → `messenger.push`, and in production `messenger.push` gives that answer. With the fake as specified, the case could never pass.
- **Fix:** The fake `push()` answers `(false, "missing_udids")` when both `udid` and `udids` are undefined, like `lib/thinx/messenger.js:965`.
- **Files modified:** `spec/jasmine/DeviceOwnershipSpec.js`
- **Committed in:** `199ec9f2`

**2. [Rule 2 - Correctness] The real modules are pre-required before the cache swap**
- **Found during:** Task 1
- **Issue:** Requiring only `router.js`/`util.js` before the swap would let any module that is first loaded while the swap is active capture the fake couch at module level. That module would then stay in `require.cache` after afterAll and leak into later spec files in CI's single process.
- **Fix:** The outer beforeAll also requires the real `device.js`, `devices.js` and `transfer.js` first, so their whole dependency tree binds the real modules. Only then does it save the seven entries, swap, delete and re-require. The six-spec combined run (244 specs, 0 failures) confirms there is no leak.
- **Committed in:** `199ec9f2`

**3. Commit signing.** GPG is locked (`gpg: cannot open '/dev/tty'`). All four commits used `git -c commit.gpgsign=false commit`, the operator's standing exception. `--no-verify` was never used.
