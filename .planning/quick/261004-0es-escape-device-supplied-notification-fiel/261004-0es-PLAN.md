# Quick 261004-0es: escape device-supplied notification fields in classic console toasts

<objective>
Found by quick 261003-vn3 (open question 1) and widened on orchestrator review. Before vn3, actionable frames never reached a socket (the old send path threw). vn3 now delivers them to the device's owner — including frames published by a transferred device's previous owner via vbg's transfer binding. `src/app/js/controllers/LogviewController.js` (≈ lines 210–330, the websocket message handler) builds toastr HTML by string concatenation:
- actionable bool/string: `msg.body`, `msg.nid` (also in `id="okBtn-…"`, `name="reply-…"`, and jQuery selectors `$("#okBtn-" + msg.nid)`), `msg.title`.
- status and plain notifications: `JSON.stringify(msg.body)` (does not escape `<`) and `msg.title`; `toastr[msg.type](…)` indexes toastr with an attacker-controlled key.
The CSP blocks inline script, so the impact is markup/phishing injection (fake prompts, links, overlays) into another owner's console. Client-side escaping keeps the frame payload byte-identical (vn3/vbg contracts).
</objective>
