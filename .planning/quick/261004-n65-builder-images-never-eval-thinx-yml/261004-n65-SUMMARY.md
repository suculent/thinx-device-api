# Quick 261004-n65: builder images never eval thinx.yml (T-23-14) Summary

**The arduino, platformio, nodemcu and micropython build images now read thinx.yml through `thinx_yml_load`, the worker's awk loader with a per-image allowlist, so a `$(...)`, backtick or quote break-out in a repository's thinx.yml (or in the devsec values the API writes into it) no longer runs as shell in the build container, and micropython no longer prints the parse into the build log.**

## What changed

**cmd.sh in each repo**
- `parse_yaml` is replaced by `thinx_yml_load FILE`. The function is the same in all four repos except its doc comment and its `case` arms. The awk program is byte-identical, which was checked with `diff`.
  - The grammar is m46's: `key: "..."` / `key: ...` / `- item`, names joined with `_`, CR stripped.
  - Multi-line and control-character values are rejected (NUL is mapped to \001 first).
  - Nothing is exported or printed.
- There is one grammar addition over the worker loader. A double-quoted list item `- "x"` has its quotes dropped and `\"`/`\\` decoded, because the old eval did the same (`(""x"")`).
- List semantics are reproduced per reader (see key-decisions). The awk emits `name+=value` for a trailing-`_` name, which is the old `sed 's/_=/+=/g'`.
- The load line in each cmd.sh:
  - arduino: `thinx_yml_load "$YMLFILE"`
  - platformio: `thinx_yml_load "$YMLFILE"`
  - nodemcu: `thinx_yml_load "$WORKDIR/thinx.yml"`
  - micropython: `thinx_yml_load thinx.yml`
- micropython: `parse_yaml thinx.yml` (the devsec print) and the eval are gone, and `echo "Reading thinx.yml:"` is now `echo "Reading thinx.yml"`.

**tests/thinx-yml-loader.sh in each repo.** This is plain POSIX sh and runs under bash, dash or busybox with any awk.
- It extracts cmd.sh's top-level functions and its thinx.yml load line, then runs that load step in a subshell with `set -e`, with the case dir as cwd. `YMLFILE` and `WORKDIR` point at it.
- Wiring checks:
  - no `eval`;
  - no `parse_yaml`;
  - no sourcing of a yml;
  - micropython only: no printing of thinx.yml;
  - the load line calls `thinx_yml_load`.
- Marker cases: `$(touch PWNED)`, backticks and `x"); touch PWNED; #`. Each is tried as a plain value, as a double-quoted value, as list items, under names cmd.sh does not read (devsec, others), multi-line, and with control characters. Each case asserts that no PWNED file appears and that the value arrived literally.
- Legit layouts with their expected values, written out in the test:
  - arduino: both `tests/dummy-*` projects, the spec/test_repositories/arduino layout, the libs list (first item), a scalar libs, quoted items and escapes, last-key-wins, CRLF, a missing file;
  - platformio: thinx-autoflood, the README example, both thinx-firmware-*-pio layouts, a target list;
  - nodemcu: the README format;
  - micropython: platform plus a modules list.
- Every `expect` also asserts that the load step printed nothing and left unread names unset.

**Docs (arduino only):** a CHANGELOG `0.8.220` entry, and a CLAUDE.md convention that thinx.yml is never eval'd and a new key needs a `case` arm. platformio, nodemcu and micropython have no CHANGELOG or CLAUDE.md.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The port needed the builders' array semantics, not the worker's**
- **Found during:** arduino. The builders' parse_yaml emits `name=("v")` and rewrites list items to `name+=("v")`; the worker's emits scalars and drops the trailing `_`. A straight port would have changed values. Example: arduino_libs, which the todo described as "keeps only the last item" (that is the worker's behaviour). Here the images read `${name}`, which is the **first** item.
- **Fix:** the awk marks append, and each case arm reproduces what its reader saw. Quoted list items are dequoted as eval did. Parity is shown above.
- **Commits:** 7841df0, 5cdabaf, 711aa42, c2487e6

**2. CI wiring in the test commit.** The plan asked for wiring only where a CI test step exists. arduino and platformio have one. nodemcu's `test-docker-build` job was treated as one and wired, though it does not gate deploy. micropython has no test step and was not wired.

**3. Commits on master/main** of each builder repo, as instructed. The executor's protected-branch guard would otherwise refuse.

### Deliberate value differences from the old eval (none occur in any legit fixture)
- Plain values containing `$`, `` ` ``, `"` or `\` are literal. Before, they were expanded or executed, or an unbalanced `"` broke the whole eval.
- Whitespace inside a value is kept as written. The old unquoted `$(...)` word-split and re-joined the text, which collapsed runs of spaces and tabs to one space. Example: `"80\t000"` used to become `80 000`.
- CR from CRLF files is stripped. Before, unquoted values kept `\r`.
- `_=` inside a value is kept. The old `sed 's/_=/+=/g'` rewrote it.
- Inline `# comments` after a value stay part of the value. Before, `#` commented out the rest of the eval line, which held every later assignment.
- `- ""` sets nothing. Before, it appended an empty element.
- Block scalars and other multi-line values are left unset. Before, the variable got the header (`|`, `>-`) or the first line.
- An environment variable of an allowlisted name that is already set is handled as bash handled it. A list item does not override it for `${name}` readers, and is appended for `${name[@]}` readers. The worker passes no such variables.
