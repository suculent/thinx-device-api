# Quick 261004-m46: Worker never evals repository thinx.yml (T-23-14) Summary

**`builder` and `infer_platform` now read thinx.yml through `thinx_yml_load`, an awk parser that assigns only allowlisted names with literal values. A `$(...)`, backtick or quote break-out in a repository's thinx.yml no longer runs as root on the swarm host. Devsec credentials are no longer echoed to the build log.**

## What changed

**`builder-lib.sh`: `thinx_yml_load FILE SCOPE`**
- Runs `tr '\000' '\001' < FILE | awk ...`. The awk reproduces the old parse_yaml grammar:
  - `key: "..."` or `key: ...` / `- item`;
  - name = parent keys joined with `_`, at two spaces per level, using the same `vname[]` code;
  - the trailing `_` that `sed 's/_=/=/g'` removed is still removed.
- The awk prints `name=value` lines into a variable. A `while IFS= read -r` loop over a here-document then assigns through `case "$2:$name"`, with 7 `builder:` entries and 5 `infer:` entries. Any other name or scope is ignored.
- No eval, no `printf -v` (busybox ash lacks it), no `export`, no output. Temporary variables are unset afterwards.
- Trailing CR is stripped, so CRLF files are handled.
- Rejected, leaving the variable as it was:
  - control characters other than tab, including NUL (mapped to \001 first);
  - block-scalar headers;
  - any value followed by a continuation line (folded or multi-line quoted).

**`builder`**
- `PARSED=$(parse_yaml ...); eval "$PARSED"` is replaced by `thinx_yml_load "$YML" builder`.
- The "Overriding devsec_* from environment.json" lines no longer print the value.
- The three `[REM DevSec] devsec_*: ...` debug lines are removed.
- The "Skipping, configuration incomplete" line prints `CKEY: set|missing` instead of the key.
- The NBSP-containing `source ./infer` comment is replaced.

**`infer`**
- `parse_yaml` is removed. Nothing else used it.
- The override block uses `local platformio="" arduino="" micropython="" mongoose="" nodejs=""` and then `thinx_yml_load "$YMLFILE" infer`, so values inherited from the caller cannot pick the platform.
- `platform = "x"` → `platform="x"` (5×). The old form ran a command named `platform` and failed with "not found". `$microphython` → `$micropython`.

**Docs:** the `class.js` comment no longer says the builder evals YAML. The worker CLAUDE.md test count is now 125, with a "thinx.yml is never eval'd" note.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Security] devsec values were echoed to stdout and $LOG_PATH**
- **Found during:** Task 1. This is a must-have truth, and builder broke it in 7 places: 3 "Overriding devsec_*: value" lines, 3 "[REM DevSec]" lines, and CKEY in the "Skipping" line.
- **Fix:** Values were removed from all of them. A wiring test fails on any `echo`/`printf` line that references `$devsec_ssid|pass|ckey`.
- **Commit:** 192521b

**2. [Rule 1 - Bug] infer override fixed: `platform = "…"` → `platform="…"`, `microphython` → `micropython`**
- The plan allowed this only if fixture platforms stay the same. They do: all 6 repo dirs match the baseline, and so do the 4 test layouts. The override fires only for a top-level scalar such as `nodejs: true`. Section mappings (`platformio:` with children) produce no value, under parse_yaml before and under the loader now.
- **Commit:** 192521b

**3. Deliberate value differences from the old eval. None of them occur in any repo fixture.**
- A plain value containing `$`, `` ` ``, `"` or `\` is now literal. Before, it was expanded or executed, or, with an unbalanced `"`, the whole eval failed and every variable stayed unset.
- `_=` inside a value is kept. The old `sed 's/_=/=/g'` also rewrote it inside values.
- CR from CRLF files is stripped. Before, unquoted values kept `\r`.
- `|-` / `>` block scalars and other multi-line values are left unset. Before, the variable got the literal `|-` or the first line only.
- Values are no longer `export`ed.

**4. Name list is narrower than the plan's examples**
- platformio_environment, platformio_target, environment_target and arduino_* are not assigned, because nothing in builder, infer or builder-lib.sh reads them. The plan says to allow "ONLY ... the scripts actually read". micropython_platform is kept: the plan names it and builder defaults it, but nothing reads it.

**5. Committed on the worker's `main`.** This follows the orchestrator's instruction, as in lps. The executor's protected-branch guard would otherwise refuse it.

## Open questions

1. **CI:** the worker CircleCI `test` job still runs only `npm install`, so none of these 40 cases (or lps's 25) run in CI. Same question as lps: make it `npm test`?
2. builder's DevSec block writes `$DEVSEC_CONTENTS` (the signature header derived from ssid/pass/ckey) to `$LOG_PATH` with `>`. That puts derived secret material in the log and truncates everything logged before it. Should it be removed? It is outside this plan's scope.
3. `"$THINX_ROOT/devsec" -s ${devsec_ssid} -p ${devsec_pass}` runs with `IFS='+'` and the variables unquoted. A repository or device value containing `*`, `?` or `[` is glob-expanded against the cwd. This does not execute anything, but it can corrupt the signature. The same applies to `devsec_pass=$(echo ${VAL} | sed ...)` reading environment.json. Quote them in a follow-up?
4. YAML.stringify emits **single-quoted** values when a string needs quoting and contains `"`, for example a Wi-Fi password `a: b"c`. The old code broke the whole eval on these. The loader now keeps them literal, quotes included, so the value matches neither the old code nor YAML. Proper single-quote support was left out because it would change values for hand-written `'...'` entries, which used to keep their quotes. Decide which behaviour you want.
5. The worker still has to be pushed (`main`: lps's 3 commits plus these 2), and the parent gitlink bumped on `thinx-staging`. After the image publishes, run one real devsec plus platformio build (coverage M3).
