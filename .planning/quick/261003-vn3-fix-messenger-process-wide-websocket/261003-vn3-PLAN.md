Resolve todo `.planning/todos/pending/2026-10-03-messenger-websocket-is-process-wide.md` (threat T-v05-07, which quick 261003-v05 transferred to this task). The Messenger singleton keeps one socket field, set by whichever owner's socket sent `init` last, and every console writer sends to it. After this task, every outbound console frame goes to the sockets of the owner it belongs to, and to no other socket.

**What the code does today** (verified during planning; details in `<context>` M1-M10):
- `initWithOwner` overwrites one process-wide field with the socket that sent init. Four writers send to that field:
  - the Slack RTM forwarder
  - the check-in/out and connected/disconnected helper
  - actionable notifications
  - the unknown-message debug notice
- Three of those writers compare `readyState` with the OPEN constant of a property that is always null. Once any socket has sent init, each call throws `TypeError: Cannot read properties of null (reading 'OPEN')` (reproduced). So in practice no frame was delivered, and the cross-owner delivery was latent. Fixing that TypeError on its own would have made it live, which is why the routing has to change in the same commit as the send path.

**Design** (Claude's discretion, recorded for the SUMMARY):
- **Subscriptions live in the Messenger:** a Map from owner to a Set of sockets, keyed by the socket's verified owner. Sockets join only through `initWithOwner`. After v05, the only caller is `SocketSession.onMessage`, which passes `ws.owner` (the session owner checked against the path at accept) and the socket the frame arrived on.
- **Subscription by init.** Today's semantics are that the socket which sent init gets notifications. The classic console sends init on its owner connection (`/<owner>`). Its log connection (`/<owner>/<ts>`) never sends init, and it appends every frame to the log view, so notification frames must not go there.
- **Defence in depth:** `initWithOwner` refuses a socket whose `owner` is not the owner being initialized.
- **Cleanup:** a 'close' listener per subscribed socket, a prune of non-OPEN sockets at send time, and an owner entry is deleted when its Set is empty.
- **app._ws** (`SocketSession`'s registry): after v05 nothing reads it. Still, every console page load adds a `/<owner>/<ts>` entry that is never removed, so Task 2 deletes an entry on close when it still points at that connection.
- **Unknown owner:** a missing, non-string or empty owner is dropped with one log line without payload. A valid owner with no subscribers is silently skipped, which is the normal case when no console is open, so it adds no log noise.
- **No change to thinx-core.js.** v05's wiring (`messenger: app.messenger`, init → `initWithOwner(ws.owner, ws, …)`) is pinned statically.
