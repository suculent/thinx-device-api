That closes the substring bypass, the device-path fall-open in `log_invalid_key`, and the `ott`+`forced` firmware bypass. The router body path, the CI test bypass and the login hash compare were moved to exact matching too.

## What changed

- `lib/thinx/util.js`: `Util.safeEqual(a, b)` returns false unless both inputs are non-empty strings. It compares utf8 byte lengths, which keeps `timingSafeEqual` from throwing on multibyte input, then calls `crypto.timingSafeEqual`.
- `lib/thinx/apikey.js`:
  - `key_in_keys` returns false for a non-string or empty key and for malformed or non-array stored JSON (logs one warning without the stored content). It skips null or non-object entries and matches with `Util.safeEqual` against `.key` or `.hash`. No `indexOf` remains in the file.
  - `verify` rejects a non-string or empty key before Redis. The CI key is now the module constant `TEST_ENV_APIKEY`, matched exactly and only when `ENVIRONMENT === "test"`.
  - `log_invalid_key` always answers `(false, "owner_found_but_no_key")` and logs the redacted warning for every caller. `is_http` is kept for compatibility and documented as informational.
- `lib/thinx/device.js`:
  - `firmware()` rejects when `success !== true`, before the device lookup, whatever `ott` or `forced` say.
  - The register and firmware audit lines log `Util.redactToken(api_key)`. The firmware line now reads "on firmware update" instead of the copy-pasted "on device registration". No spec asserts that string.
- `lib/router.js`: the body owner/api_key path calls `sanitka.apiKey(api_key)` in place of `sanitka.udid(api_key)`.
- `lib/router.auth.js`: `rejectLogin` uses `!Util.safeEqual(password, user_data.password)`. Both branches are unchanged.

## rejectLogin rationale

The login check used the same pattern as CR-01, `password.indexOf(user_data.password) === -1`, which is a substring search standing in for an equality check. It was not practically exploitable. The search term is the stored hash, which the server controls, and every writer stores a 64-hex sha256 (`lib/thinx/owner.js:644,675`). Only an empty stored password would have let any password in, because `indexOf("")` is 0. It now uses an exact constant-time compare:
- A missing stored password (undefined/null) still answers `password_missing`.
- Any other mismatch, including an empty stored string, answers 401 `password_mismatch`.

## Operator-facing behavior changes (read before pushing)

1. **Device firmware and OTT requests now fail closed on a wrong key.** `/device/firmware` and the OTT request used to accept any `Authentication` value for a known owner. That was the fall-open in `log_invalid_key`, plus the `ott`+`forced` skip in `firmware()`. They now require the exact stored key or its hash. Devices with stale or revoked keys, and THiNX-built firmware that carries the masked key (see todo 2), will stop receiving OTA. Undoing this after rollout takes a production redeploy.
2. **The router body path now accepts the full key.** A POST body `{owner, api_key}` authenticates with the full 64-char key or hash. Before, only a 36-char slice could pass. Its CSRF exemption stays limited to cookieless calls by `lib/middleware/csrf.js` (D-09 / 25-REVIEW CR-01).
3. **Login with an empty stored password** is now rejected (401 `password_mismatch`). Before, any password was accepted.
