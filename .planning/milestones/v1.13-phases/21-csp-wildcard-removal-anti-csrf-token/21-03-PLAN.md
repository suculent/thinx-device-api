<objective>
Remove the `https:`/`wss:` scheme-wildcard from `default-src`/`connect-src` in all three CSP sources and replace it with an explicit, enumerated host allowlist (SEC-CSP-01), per the locked design in `21-CONTEXT.md`. This plan FIRST enumerates exactly which third-party hosts the two consoles load (so the pinned list isn't guesswork), THEN applies the identical pinned list to all three sources.

Purpose: close the HawkScan "CSP: Wildcard Directive" (plugin 10055-4) finding without breaking the Crisp chat widget, Google Fonts, Google Analytics, or Rollbar error reporting that the consoles actually rely on.
Output: `services/console/src/default.conf` and `services/console/vue/default.conf` (submodule) plus the two runbook snapshot files (parent repo) all carry the same pinned CSP host list.

CROSS-REPO NOTE: Task 1 touches files inside the `services/console` git submodule; Task 2 touches files in the parent `thinx-device-api` repo. These are two separate commits in two separate repos — do not attempt to commit both in one `git commit` invocation.

The existing `form-action 'self' <PLACEHOLDER> https://github.com` stays as-is (unrelated to this fix — `form-action` already explicitly allowlists github.com, was never wildcarded).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Console page (any origin an attacker fully controls if XSS'd) -> browser's CSP enforcement | The `https:` wildcard previously allowed script/connect to ANY HTTPS host, defeating CSP's main purpose as an XSS-exfiltration/injection backstop |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-07 | Elevation of Privilege / Tampering | `default-src`/`connect-src` `https:` scheme wildcard | mitigate | Replace with the explicit pinned host allowlist in all three sources (Task 1 + Task 2) |
| T-21-08 | Information Disclosure (XSS exfiltration via an unpinned third-party host) | Same directives | mitigate | Only `rtm.thinx.cloud`, `console.thinx.cloud`, `*.crisp.chat`, `fonts.googleapis.com`, `fonts.gstatic.com`, `www.google-analytics.com`, `api.rollbar.com` remain reachable — an XSS payload can no longer `fetch()`/`beacon` to an arbitrary attacker-controlled HTTPS endpoint |
| T-21-09 | Elevation of Privilege (`'unsafe-inline'`/`'unsafe-eval'` XSS surface) | Same directives | accept (deferred SEC-CSP-02) | AngularJS `$parse` needs `'unsafe-eval'` in the legacy console; blocked on the AngularJS -> Vue migration completing. This plan does not add or remove either token in any of the three sources — pre-existing token sets are preserved as-is |
| T-21-10 | Tampering (config drift between the 3 CSP sources) | Console images vs. runbook audit doc | mitigate | Identical pinned host list applied to all three sources in this same plan; Plan 21-04's functional-verify checkpoint confirms via browser DevTools that the EFFECTIVE policy (whichever image serves the request) matches |

No package-manager installs are part of this plan.
