## Milestone Summary

**Decimal Phases:** None.

**Key Decisions:**

- SEC-CSP-01 and SEC-CSRF-01 combined into one phase (granularity coarse) — same three deploy surfaces, same two-console consistency check.
- CSRF scheme is **double-submit cookie** (not a server-side synchronizer token as REQUIREMENTS originally worded) — stateless, works identically for both frontends across the `app.`/`console.`/`rtm.` subdomains.
- Fail-open rollout first (21-04), enforcement flip second (21-05) — lets both consoles be verified live before a bad token could lock anyone out.
- Console wiring via two shared seams instead of per-call-site edits — four plan-check passes each found missed call sites.
- HawkScan acceptance criteria waived by operator override after StackHawk was removed (`bb0ce4a7`); substitute evidence = repo-wide CSP parse, CSRF unit specs, live probes, operator cold-browser approval.
- `POST /api/v2/user` left unprotected (WR-04) because it is a documented public registration endpoint for non-browser clients.

**Issues Resolved:**

- CSP `https:`/`wss:` scheme wildcard removed from all repo sources and the live gluster CSP.
- Login/account POSTs without a matching CSRF token are rejected (403 `csrf_token_invalid`) in production.
- Discovered and documented that production console CSP comes from `/mnt/gluster/deployment/swarm/console/default.conf` (bind mount), not the images.
- Topology drift corrected: `thinx_api` on core, `thinx_console` on micro, `thinx_vue` on core (2026-09-21).

**Issues Deferred:**

- **SEC-CSP-02** — `unsafe-eval` removal, blocked on AngularJS retirement.
- **WR-06** — double-submit cookie on `.thinx.cloud` gives no same-site protection; session-bound HMAC token + guarding session-mutation routes is an architectural follow-up.
- **WR-04** — decide whether `POST /api/v2/user` must stay open to machine clients.
- Classic register / forgot-password / reset-confirm flows under enforcement not spot-checked in a browser (verifier's one behaviour-unverified item).

**Technical Debt Incurred:**

- Image `default.conf` files (classic + Vue) diverge from the production gluster file; the retirement path in `console-csp-source-of-truth.md` (align images, drop bind mount) is not done. Vue `connect-src` omits `app.thinx.cloud` — a latent lockout if the mount is ever removed.
- `.planning/runbooks/swarm-configs/rtm.thinx.cloud-server.{pre,post}.nginx` CSP snapshots are stale versus the live header.
- `:vue` image is built with `WEB_HOSTNAME=rtm.thinx.cloud` (shared var) — cosmetic footer links point at the classic console.
