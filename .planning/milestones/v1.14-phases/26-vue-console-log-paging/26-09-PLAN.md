Facts verified at planning time (2026-10-01, by running the specs and reading the code):
- **Submodule.** `services/console` is on branch `thinx-staging`. Commit inside it with `git -C services/console …`. Do not push and do not bump the parent gitlink; plan 26-07 does both.
- **Why the harness fails today.** On unchanged code, history.spec.js, dashboard.spec.js and device-detail.spec.js all fail locally (7 failing, 13 skipped). There are two causes, both pre-existing:
  - (a) Since the console commit "keep session tokens out of browser storage", `auth/hydrateSession` exchanges the session cookie through `POST /api/v2/session/token`. The stubs leave that call unstubbed (the catch-all answers 500), so `visitApp({session:true})` lands on /login. A planning-time experiment adding that intercept inside visitApp took dashboard.spec.js from 0/8 to 8/8 passing.
  - (b) After hydrate, App.vue pushes /app/dashboard because it reads `$router.history.current.path` before the initial navigation confirms. Deep links such as `/#/app/history` therefore land on the dashboard. A planning-time probe that visited the dashboard and then set `window.location.hash = '#/app/history'` loaded History with all stubs hit.
  The App.vue deep-link redirect is a real but pre-existing app bug outside this phase. Do not change App.vue or the auth store; record it as a SUMMARY follow-up.
- **Stubs.** `cy.stubThinxApi()` registers a catch-all for `/api/v2/` first, then named intercepts such as `@getAuditLog` and `@getBuildLog` (pathname match on `/api/v2/logs/audit` and `/api/v2/logs/build`). A bespoke paged intercept must be registered after `cy.stubThinxApi()` (26-RESEARCH.md Pitfall 11), and it must branch on the `cursor` query parameter inside its handler. Keep `audit-log.json` and `build-log.json` unchanged: they have no `paging`, so has_more is false.
- **Dashboard entry side effect.** `visitAppRoute` passes through the dashboard, which also requests the first audit and build pages. A `cy.wait('@…')` after it can therefore match the dashboard's request. Assert on rendered History rows (Cypress retries `should`), and take any request-count snapshot only after History's rows are visible.
- **History hooks (plan 26-05).** `data-cy` values: `audit-paging`/`build-paging`, `audit-load-more`/`build-load-more`, `audit-filter-hint`/`build-filter-hint`, `audit-load-more-error`/`build-load-more-error`, `audit-paging-status`/`build-paging-status`. Button aria-labels: "Load more audit log entries" and "Load more builds". Copy is verbatim from 26-UI-SPEC.md "Copywriting Contract". If 26-05-SUMMARY records a deviation from these names, follow the SUMMARY.
- **Cypress command.** `npx start-server-and-test 'npm run serve' http://127.0.0.1:3000/ 'npx cypress run --spec …'`, run from `services/console/vue` (Cypress 9.7, dev server on :3000, about 3 minutes for three specs). Never run `login.spec.js` or the full suite: login.spec.js calls the live API.
