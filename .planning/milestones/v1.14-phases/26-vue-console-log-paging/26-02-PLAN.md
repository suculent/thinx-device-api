Facts verified at planning time (2026-10-01):
- `Util.responder(res, ok, msg)` always emits exactly `{success, response}`; `Util.respond(res, obj)` JSON-stringifies any object with the JSON content type; `Util.failureResponse(res, code, reason)` sets the status then calls responder. `Util.validateSession(req)` calls `req.session.destroy()` when it returns false, so fake requests need a `session.destroy`.
- Express 5 `query parser` is `simple`: `?cursor=a&cursor=b` yields an array. nano JSON-encodes `startkey`/`endkey`/`key` but passes `startkey_docid` raw (node_modules/nano/lib/nano.js:341-345).
- `buildlog.js` builds `buildlib` at module load (`require("./couch")(db_uri).use(prefix + "managed_builds")`); specs stub couch.js in require.cache and require buildlog.js fresh (same rule as plan 26-01: restore cache in afterAll).
- Today `list()` queries `builds/latest_builds` without a key (all tenants), filters by owner in memory, and "prunes" with a call that is a no-op (production `doc_del_count: 0`). `latest_builds` emits `(doc.owner, doc)`, so nested docs key as null. `getBuildLogs` transforms rows (docs with `log` → that doc with `log` reduced to its latest line; without → `{date: timestamp, udid}`).
