# Phase 26 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** a small, additive change to one existing page (`services/console/vue/src/pages/History/History.vue`) plus a store/API-client change that the dashboard consumes without any visual change. No new design system and no new dependency. Everything below reuses the tokens and components the Light Blue / bootstrap-vue theme already ships.

**Locked upstream (26-CONTEXT.md, not re-opened):** D-01 "Load more" button under each table, appends, disappears when `has_more` is false. D-02 page size 100. D-03 the two tables page independently. D-04 dashboard fetches the first page only. D-05 filters stay client-side over loaded entries, with an "older entries exist" hint next to Load more when a filter is active and `has_more` is true. No automatic page loading. D-06 no date jump. D-19 `Api.parseResult` keeps `paging`.

**Not applied:** the repo's `corporate-webdesign-identity` skill (Corpus/CDIP apps). The THiNX console has its own theme.

## Spacing Scale

Existing pages use Bootstrap 4 spacing utilities (`mb-2`, `mb-3`, `mr-2`, `mr-3`). Because the root font size is 14px, those resolve to 3.5 / 7 / 14 / 21px, which are not multiples of 4. This phase does **not** touch existing spacing. New elements use the px values below through a scoped style block in History.vue (the page already sets inline px styles such as `max-width:180px`).

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between icon/spinner and its text (hint, error, button label) |
| sm | 8px | Paging footer top margin (gap between table or empty-state line and the footer); row gap when the footer wraps |
| md | 16px | Horizontal gap between Load more and the hint / error; footer bottom margin |
| lg | 24px | Not used by new elements |
| xl | 32px | Not used by new elements |
| 2xl | 48px | Not used by new elements |
| 3xl | 64px | Not used by new elements |

Exceptions:
- `btn-sm` padding (3.5px / 7px at the 14px root) is an **inherited theme value**, not a new token. Do not copy it into new spacing.
- Load more button `min-width: 112px` so its width does not jump between "Load more" and spinner plus "Loading…".
- Button internal padding stays Bootstrap `btn-sm` (0.25rem / 0.5rem = 3.5px / 7px at 14px root). Do not override it; it matches every other `size="sm"` button in the console. Rendered height is about 27px, which clears the WCAG 2.2 SC 2.5.8 24px minimum target.
- Existing rem-based utility spacing elsewhere on the page is out of scope.

## Color

The console is a dark theme. Contrast numbers are computed against the tab panel surface (`$violet` #333867 under `$widget-bg` rgba(0,0,0,.24), effective #272B4E, the lightest point of the gradient and therefore the worst case).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `$violet` #333867 → #17193B radial gradient (`$default-bg`) | Page background |
| Secondary (30%) | `$widget-bg` rgba(0,0,0,.24) | Tab content panel (`.tab-content`), dashboard cards, table striping |
| Accent (10%) | `$blue` #2477FF (theme `primary`) | Reserved list below. Not used to fill the Load more button |
| Destructive | `$red` #C93C3C (theme `danger`) | The error icon in the Load more failure line, plus the existing danger badges and `table-danger` rows. No destructive actions in this phase |
| Button text | `$header-color` rgba(244,244,245,.9) | Forced on every `.btn` by `_overrides.scss`; about 10:1 on the panel |
| Hint and error text | `$text-color` rgba(244,244,245,.6) (inherited body color) | About 5.5:1 on the panel; passes 4.5:1 for 12.25px text |
| Button border | theme `secondary` rgba(52,97,193,.9) via `outline-secondary` | Decorative boundary; the label identifies the control |

Accent reserved for:
1. The keyboard focus ring on the Load more button (`outline: 2px solid #2477FF; outline-offset: 2px` on `:focus-visible`, scoped). The theme strips `box-shadow` from `.btn:not(.active)`, so without this the button has no visible focus.
2. Existing links ("View all →" on the dashboard) and the existing primary "Download" button on the dashboard. Unchanged.

Hard rules:
- Do **not** put `.text-muted` on the hint or error. In this theme `$text-muted` is rgba(244,244,245,.42), about 3.5:1 on the panel, which fails 4.5:1 at this size. The existing muted empty-state lines are left as they are.
- Do **not** use `text-danger` for error text: #C93C3C on the panel is about 2.6:1. Red goes on the icon only; the sentence uses the inherited body color.

## Interaction Contract

### Layout per table (identical structure on Audit Log and Build Log tabs)

**Visual hierarchy:** the Load more button is the primary anchor of the paging footer. The filter hint and the error line are secondary text beside it. The rest of History.vue keeps its existing hierarchy.

```
[existing filters: From / To dates, search, (audit only) flag switches]
[existing empty-state line  OR  existing table]
<div class="log-paging" data-cy="{audit|build}-paging" tabindex="-1" :aria-busy>   <- NEW, always rendered
   [Load more]  (i) Filtering 300 loaded entries; older entries exist.
   (!) Couldn't load older entries. Select Load more to try again.
</div>
<div class="sr-only" aria-live="polite" data-cy="{audit|build}-paging-status">…</div>  <- NEW
```

- The footer sits **after** the `v-if` empty-state div / `v-else` table pair, **outside** both branches. A filter that matches nothing must never hide Load more, or the user could not reach older entries (26-RESEARCH.md, Vue store contract).
- `.log-paging`: `display:flex; flex-wrap:wrap; align-items:center; gap:8px 16px; margin-top:8px; margin-bottom:16px;`. Put `v-if` on the inner items only, so the wrapper stays in the DOM as a focus target. Add `.log-paging:empty { margin:0; }`: Vue leaves only comment placeholders for false `v-if`s, and CSS `:empty` ignores comments, so an idle wrapper takes no space.
- Button left, hint to its right, error after the hint. On narrow widths the items wrap onto the next line with an 8px row gap.

### Load more button

| State | Condition | Rendering |
|-------|-----------|-----------|
| Hidden | table's `has_more` is false | Not rendered (D-01) |
| Idle | `has_more` true, not loading | `<b-button variant="outline-secondary" size="sm">Load more</b-button>`, `min-width:112px` |
| Loading | request for this table in flight | Label becomes `<b-spinner small aria-hidden="true" />` + 4px gap + "Loading…". Set `aria-disabled="true"` and class `disabled`; the click handler no-ops while loading. **Do not set the native `disabled` attribute**, because that drops keyboard focus to `<body>` mid-request |
| Error | last request for this table failed | Button returns to Idle so it is the retry control. The error line shows (see below) |

- A click requests the next 100 entries for **that table only**, using that table's cursor (D-02, D-03). The other table's rows, cursor, button, hint and error do not change.
- Appended rows go to the end of the existing list. Existing rows keep their position, filters stay applied, and expanded build logs stay expanded (expansion is keyed by `build_id`).
- After a successful append:
  - If `has_more` is still true, focus stays on the button.
  - If `has_more` is now false, the button disappears. If it had focus, move focus to the `.log-paging` wrapper (`tabindex="-1"`) so keyboard users are not dropped to `<body>`.
- Double clicks and Enter repeats while loading send no second request.

### Filter hint (D-05)

- Shown when **both** are true for that table: `has_more` is true, and a filter is active.
  - Audit filter active: `dateFrom || dateTo || auditSearch.trim() || auditFlagFilter.length !== 3`.
  - Build filter active: `dateFrom || dateTo || buildSearch.trim()`.
  - Text search counts as a filter because it also runs client-side over loaded entries (26-RESEARCH.md discretion call).
- Hidden when `has_more` is false (all entries are loaded, so the filter result is complete) or when no filter is active.
- Never triggers page loads (D-05: no automatic loading).
- Markup: `<span data-cy="{audit|build}-filter-hint"><i class="la la-info-circle" aria-hidden="true"></i> Filtering …</span>`, body color, 12.25px.
- The date range is shared by both tabs (existing behaviour: one `dateFrom`/`dateTo`), so a date filter can show the hint on both tables at once. Each table still decides from its own `has_more`.

### Error line

- Shown after a failed Load more for that table: network rejection, non-success response, or a 400 on a bad cursor.
- Markup: `<span role="alert" data-cy="{audit|build}-load-more-error"><i class="la la-exclamation-circle text-danger" aria-hidden="true"></i> Couldn't load older entries. Select Load more to try again.</span>`, body color text.
- Already loaded rows stay. `has_more` and the cursor stay as they were, so the retry asks for the same page.
- Cleared when the user clicks Load more again, and on a successful append.
- The store action must report failure to the page (return a status or throw). The research sketch's `try/finally` swallows errors; the planner must not ship it that way.

### Initial load (existing, one fix)

- The existing full-page "Loading..." line and the first-page fetch of both tables stay as they are. They now request `limit=100` and read `paging` (D-02).
- Fix in passing: `loading` must clear when the first-page `Promise.all` rejects (use `.finally`). Today a network failure leaves "Loading..." on screen indefinitely. After a rejection, each table shows its existing empty-state line with no Load more.

### List integrity while on History

- While History is mounted, its loaded rows and cursors must **not** shrink, reset or duplicate because something else re-fetched the first page. `Header.vue` (layout mount), `Notifications.vue` (on create) and `DeviceDetail.vue` all call `buildlog/fetchBuildLog`.
- Recommended mechanism: History keeps its own `auditlog`/`buildlog` arrays and per-table paging state, as it already copies arrays in `loadData()`. It appends only results of its own requests. The research's `generation` guard alone prevents stale appends but still lets a background first-page refresh reset a table the user has paged through. The planner picks the mechanism; the invariant is the contract.

### Dashboard (D-04): visually unchanged

- `Visits.vue` "Recent Audit Events" and "Recent Builds" cards keep their markup, the `slice(0, 10)`, the "View all →" link and the `data-cy="recent-audit"` / `"recent-builds"` hooks.
- No Load more, hint or paging status on the dashboard, Header or Notifications.
- The only visible difference is data: the widgets now show the owner's own newest entries with real flags (LOG-02/LOG-03).

### DeviceDetail

- No visual change and no Load more in this phase. Its per-device build list now derives from the owner's newest 100 builds (26-RESEARCH.md Open Question 4; D-19 leaves it to the planner, who must note it in the plan).

## Accessibility Contract

| Concern | Requirement |
|---------|-------------|
| Button name | Visible "Load more" plus `aria-label` naming the table ("Load more audit log entries" / "Load more builds"), so two same-label buttons in the DOM (both tabs render) are distinguishable |
| Busy state | `aria-busy="true"` on the table's `.log-paging` wrapper and on that table's `<table>` element while a page loads; `false` otherwise. Spinner is `aria-hidden="true"`; the "Loading…" text is the accessible state |
| Appended rows | One visually hidden live region per table (`<div class="sr-only" aria-live="polite" aria-atomic="true">`), always in the DOM, text set after each successful append to the announcement copy above. Empty at rest. Do not announce on the initial load |
| Errors | Error line has `role="alert"` (announced once on appearance). Icon is `aria-hidden` |
| Focus | Button keeps focus through loading (`aria-disabled`, not `disabled`). When the button is removed after the last page, focus moves to the `.log-paging` wrapper (`tabindex="-1"`). Visible `:focus-visible` ring as specified under Color |
| Keyboard | Button is reachable by Tab and activates with Enter and Space (native `<button>`). No keyboard trap and no auto-load on scroll |
| Contrast | Hint and error text use the body color (about 5.5:1), never `.text-muted` (about 3.5:1) or `text-danger` text (about 2.6:1) |
| Target size | `btn-sm` at about 27px tall, min-width 112px, meets WCAG 2.2 SC 2.5.8 (24×24) |

## Cypress Hooks (data-cy)

Kebab-case and table-prefixed, following the page's existing hooks (`audit-row`, `build-row`, `build-expand`). Both tabs render at once, so every new hook is unique per table. Do not reuse the duplicated `date-from` pattern.

| Hook | Element | Present when |
|------|---------|--------------|
| `audit-paging` / `build-paging` | `.log-paging` wrapper | Always (after initial load) |
| `audit-load-more` / `build-load-more` | Load more `<b-button>` | `has_more` is true |
| `audit-filter-hint` / `build-filter-hint` | Hint `<span>` | `has_more` && filter active |
| `audit-load-more-error` / `build-load-more-error` | Error `<span role="alert">` | After a failed Load more, until retry or success |
| `audit-paging-status` / `build-paging-status` | sr-only live region | Always (text empty at rest) |
| `audit-row`, `build-row`, `build-expand`, `build-log-pre`, `flag-filter`, `date-from`, `date-to` | Existing | Unchanged; existing assertions must keep passing |
| `recent-audit`, `recent-builds` | Existing dashboard cards | Unchanged |

Assertions the planner should cover (stubs per 26-RESEARCH.md "Cypress: two-page stub"; keep `audit-log.json` / `build-log.json` unchanged so they mean "no paging, `has_more` false"):
1. Legacy fixtures: no `[data-cy=audit-load-more]` / `[data-cy=build-load-more]` exists; existing row counts unchanged.
2. Page-1 fixture with `paging.has_more: true`: the button is visible. Clicking it sends a request whose query string has `limit=100` and `cursor=<page-1 next_cursor>`. Rows grow by page 2's length. When page 2 has `has_more: false`, the button is gone and the status region reads "All {N} entries loaded."
3. Independence: paging the audit table leaves the build row count and build button unchanged, and the reverse.
4. Hint: with `has_more` true, setting a date or flag filter shows the hint with the loaded count. Clearing filters hides it. With `has_more` false and a filter active, no hint.
5. Filter that matches nothing while `has_more` is true: "No loaded entries match these filters." shows, and the Load more button is still present.
6. Error: page-2 stub replies 500. The error line appears, existing rows remain, the button is still present, and a retry with a 200 stub appends and clears the error.
7. Dashboard spec: unchanged assertions pass with the paged stubs (still at most 10 rows per card).
