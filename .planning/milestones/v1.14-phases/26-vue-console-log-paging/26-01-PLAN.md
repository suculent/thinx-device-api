Facts verified at planning time (2026-10-01). Re-check before relying on them.
- `Database.init` compares `"logs"` with `"managed_logs"`, so the `existing_dbs.includes(name)` early return never fires. Every boot calls `nano.db.create`, which on an existing DB rejects with "The database could not be created, the file already exists." (statusCode 412). `handleDatabaseErrors` swallows that one, but calls `process.exit(1|2)` for anything else. `injectDesign` therefore only ever runs on a freshly created DB, which is the LOG-01 root cause. Leave the `includes` comparison as it is.
- `init` arms `setTimeout(… setInterval(compactDatabases, 1 h), 30000)`. A spec that calls `init()` keeps the jasmine process alive for 30 s plus an interval. That is why the per-DB body moves into `initDatabase(name, dbprefix)`, which specs call directly.
- `audit.js` builds `loglib` at module load from `require("./couch")(db_uri).use(prefix + "managed_logs")`. Specs replace `require.cache[require.resolve("../../lib/thinx/couch")]` with a factory, delete the cached `audit.js` and require it fresh (analog: `loadAuditFresh` in `spec/jasmine/ZZ-AuditTTLSpec.js`). In afterAll, delete both cache entries so later specs load the real modules.
- Local helper-free jasmine loads `lib/thinx/audit.js`, `buildlog.js` and `database.js` without CouchDB (config from `spec/mnt/data/conf/config.json`); nano connects lazily.
- Production: 4,945 audit docs. Every `date` is an ISO-8601 `…sss Z` string. 499 docs have no owner (login failures) and 195 carry objects in `flags`. There are 3 duplicate `(owner, date)` pairs. Of 125 build docs, 113 are nested (identity under `log[0]`, `_id == log[0].build_id`) and all times are epoch-ms numbers. `_design/logs` is rev generation 1 and its `logs_by_owner` map sha256[0:12] is `925f3cee0cc4`.
- The classic console calls `.push()` on `flags` (console `src/app/js/thinx-api.js:636,639`), so `flags` must always be an array.

<interfaces>
Design doc contracts. Plan 26-04 (retention) and plan 26-02 (paging) query these view names and value shapes. Keep them exactly as specified.

design/paging_logs.json:
- `_id` "_design/paging", `language` "javascript", `views`:
  - `audit_by_owner_date.map`: the one-line ES5 string in 26-RESEARCH.md § "Audit view", verbatim. Key `[owner, isoDate]`, value `{date, message, flags}` with string-only flags (length 1–32) and the fallback `['info']`. Emits nothing when owner is not a non-empty string or the date is missing.
  - `audit_by_date.map`: ES5, one line. Read `doc.date`. If it is a finite number, convert it with `new Date(d).toISOString()`. Return without emitting unless it is then a non-empty string. Otherwise `emit(d, doc._rev)`. Key = ISO date string, value = the doc's `_rev`. Owner-less docs ARE emitted, because retention must age them out too.

design/paging_builds.json (26-RESEARCH.md § "Build view", both map strings verbatim):
- `builds_by_owner_time`: key `[owner, time]` (time = start_time, else timestamp, else 0; epoch ms), value null; identity from `log[0]` when the root has no string owner.
- `builds_by_time`: key time (number), value `{owner, udid, build_id, rev}` (build_id falls back to doc._id); emits nothing when no numeric time exists.

lib/thinx/design_upsert.js (new):
- `canonical(v)`: deep copy with sorted object keys and every `_rev` key dropped.
- `sameDesign(a, b)`: compares `JSON.stringify(canonical(a))` with `JSON.stringify(canonical(b))`.
- `withTimeout(promise, ms)`: same shape as `lib/thinx/audit-ttl-probe.js` withTimeout. Rejects with an Error whose `reason` is "timeout".
- `loadPagingDesign(name)`: `name` is "logs" or "builds". Reads `path.join(__dirname, "../../design/paging_" + name + ".json")`. Returns the parsed object, or null on any read or parse error. Never uses `Filez.appRoot()`.
- `ensureDesignDoc(db, desired, opts)`: `opts.timeoutMs` defaults to 5000. Returns a Promise of `{ok, action, reason}`, where `action` is one of created, updated, unchanged, conflict, failed, skipped. Never rejects. Writes with the two-argument form `db.insert(doc, doc._id)` (PUT).

lib/thinx/audit.js additions:
- `Audit.VIEW_TIMEOUT_MS = 5000` (static, writable for specs); `Audit.fallbackCount = 0` (static counter, read by the plan 26-02 production probe).
- `static toAuditItem(value)`: returns `{date, message, flags}`, where flags keeps only non-empty strings of 32 characters or fewer and falls back to `["info"]`. Used by fetch here and by fetchPage in plan 26-02.
</interfaces>
