Production conventions: as in the runbook § Conventions. In short:
- `MICRO_SSH` stands for the literal manager ssh command from AGENTS.md § Deployment plus `-o BatchMode=yes -o ConnectTimeout=10`, typed in full, never wrapped or committed. `CORE_SSH` is the `core` entry from `~/.aliases`.
- A permission-classifier denial becomes a `checkpoint:human-action` with the exact command.
- Query placement first. Select containers by swarm service label, never `name=influxdb`.
- Aggregates only.
- No foreground sleep: `timeout 300 docker service update|scale` waits for convergence itself; otherwise use a bounded remote until-loop or the Monitor tool.
- Commits GPG-signed. Do not push in this plan.

Secret handling (research § Pattern 1, Pitfalls 6, 7; D-11). All on micro:
- `install -d -m 700 /dev/shm/p27` and `umask 077`.
- Values are made with `openssl rand -hex N | tr -d '\n' > file` and never echoed.
- Env files are built with printf from `$(cat file)`.
- `docker secret create NAME file`, or `… | docker secret create NAME -`.
- Never use `set -x`, never use `--influx-configs-path`, and never run `influx auth list` hoping to read a token back (2.9 stores hashed tokens).

**Rollback** (runbook § Rollback). If anything fails after the scale-to-0, run:
- `timeout 300 docker service rollback thinx_influxdb`. It returns the 1.8 spec with replicas 0, because the scale was itself a spec update.
- Then `timeout 300 docker service scale thinx_influxdb=1`.

Before the service update, `docker service scale thinx_influxdb=1` alone restores 1.8. The executor runs these restoring commands itself, then returns a `checkpoint:decision`: retry after emptying /mnt/gluster/thinx/influxdb2, or abort the window.
