D-08's goal, learned keys persisting on the data volume while seeded keys stay pinned, therefore requires the seeded file in `GlobalKnownHostsFile` and the learned file in `UserKnownHostsFile`. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repository owner → API (source url/branch) | The url and branch stored on a source are attacker-controllable text that reaches git |
| API → git/ssh child processes | argv and env cross into child processes running as root in the API container |
| Remote git server → API | A remote can answer with credential prompts, host keys and repository content (including symlinks) |
| Shared data volume (`/mnt/data`) → API | World-writable in existing deployments. Planted files there (keys, known_hosts) must not be trusted |
| Redis → API | The last-good key cache is readable/writable by anything on the redis network |
