Facts verified at planning time (2026-09-27). Re-verify them, because builder.js line numbers moved in 23-01 and 23-03.
- **Why cmd keeps shell quoting (D-01 "joining argv or equivalent").** An old worker does `CMD.split(" ")`, then `join(" ")`, then `spawn(command, { shell: true })`. A plain space-join of argv would let that shell strip the double quotes out of `--env={"KEY":"value"}` and split values containing spaces, which breaks every build with API env vars on an old worker. D-01's either-order deploy guarantee therefore needs the old quoting. The "equivalent" is a local `legacyShellCommand` that reproduces shell-escape 0.2.0 exactly. The dependency is removed, and the helper goes away together with the `cmd` field (the deferred item).
- shell-escape 0.2.0's algorithm (`node_modules/shell-escape/shell-escape.js`): an element matching `^[A-Za-z0-9_\/-]+$` passes through. Otherwise it is wrapped in single quotes with each embedded single quote replaced by the four-character sequence quote-backslash-quote-quote. Then any leading run of doubled empty quotes is removed, and a backslash-quote followed by two more quotes collapses to backslash-quote. Elements are joined with one space.
- Golden outputs, computed on 2026-09-27 with the installed shell-escape (re-capture before deleting it):
  - `["./builder","--dry-run"]` gives `'./builder' --dry-run`
  - `["./builder","--env=[]","--branch=feature/x"]` gives `'./builder' '--env=[]' '--branch=feature/x'`
  - `["./builder","--git=git@github.com:owner/repo.git","--env={\"KEY\":\"a b\"}"]` gives `'./builder' '--git=git@github.com:owner/repo.git' '--env={"KEY":"a b"}'`
  - `["./builder","--env={\"Q\":\"it's\"}"]` gives `'./builder' '--env={"Q":"it'\''s"}'`
  - `--owner=`, `--udid=` and similar are quoted because `=` is outside the safe class. An old worker's `CMD.replace("./builder", ...)` still matches inside `'./builder'`.
- After 23-01, the remaining `shell-escape` users are only in builder.js: the require, the runShell log line (~L353 pre-23-01) and the remote command (~L944). `git grep -n -e shell-escape -e shellEscape -- lib` should show only builder.js. It also appears in `IMPROVEMENTS.md` (historical doc, left as is) and in the sanitka.js header comment (updated here).
- npm: local npm is 10.8.1 and the API image uses npm 10.2.3. Both use lockfile v3. `shell-escape` is a direct dependency only, at package.json L68 and at lockfile `packages[""].dependencies` plus `packages["node_modules/shell-escape"]`, with no transitive dependents.
- Builder `lgtm` markers: `getDirectories` (two), `cleanupDeviceRepositories` (one), `processShellData` (one). LGTM.com was retired in 2022, and GitHub CodeQL ignores these markers.
