**lib/thinx/safepath.js** (new, plain `fs` and `path` only, no Globals, so it loads without config; copy finder.js's header shape and document "Never throws"):
- `isInside(root, candidate)`: a lexical check with `path.resolve` on both sides and `path.relative`. It returns true only when the relative path is non-empty, not `..`-leading and not absolute. It is used for paths that do not exist yet (BUILD_PATH in Task 3).
- `resolveInside(root, target)`, returning `{ ok, path, reason }`:
  - Validate the input: both must be non-empty strings, otherwise `invalid_input`.
  - `rootReal = fs.realpathSync(root)`. On error, `root_missing`.
  - `abs = path.resolve(root, target)`.
  - lstat `abs`. If it is missing, realpath its parent (`missing` if the parent is missing) and set `real` to the parent realpath joined with the basename, and the result carries `reason: "missing"` with `ok: false` unless the caller passes `{ allowMissing: true }`. If it is a symlink, return `symlink`. Otherwise `real = fs.realpathSync(abs)`.
  - `rel = path.relative(rootReal, real)`. When rel is empty, starts with `..` or is absolute, return `outside_root`. path.relative already separates `abc` from `abc-evil`.
- `readFileInside(root, target, encoding)`, returning `{ ok, data, reason }`: `resolveInside`, then `fs.openSync(real, fs.constants.O_RDONLY | fs.constants.O_NOFOLLOW)`, `fstatSync` must be `isFile()` (else `not_a_file`), read, and close in `finally`.
- `writeFileInside(root, target, data)`, returning `{ ok, reason }`: `resolveInside(..., { allowMissing: true })`, then open with `O_WRONLY | O_CREAT | O_TRUNC | O_NOFOLLOW` and mode `0o666` (the same default as writeFileSync), write, close in `finally`.
- `unlinkInside(root, target)`, returning a boolean: lstat. For a symlink, `fs.unlinkSync` the link itself; unlink does not follow. For a regular file, check containment with `resolveInside`, then unlink. Anything else returns false. Never throws.
- Every catch maps to `io_error`. Why comment: realpath on both sides plus `O_NOFOLLOW` closes the check-then-open window for the final component.
