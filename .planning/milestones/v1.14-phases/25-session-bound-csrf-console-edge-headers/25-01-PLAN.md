<objective>
Build the session-bound CSRF token and the login rotation seam, proven locally end to end.

The tracer (Task 1) wires one path through every layer this plan touches: the priming GET creates a 15-minute pre-session and mints an HMAC token bound to `req.sessionID`, a password login verifies it, regenerates the session and sets a rotated token in the login response, the rotated token passes a guarded route and the old one is refused, and logout clears the cookie. Task 2 hardens the key (module scope, `CSRF_SECRET` then HKDF then fail closed), adds the fail-closed start in `thinx-core.js`, pins the legacy rollback contract and rewrites `ZZ-CSRFSpec.js`.

Purpose: SEC-CSRF-02 (signed, session-bound token, pre-session, re-mint, key, `CSRF_MODE`) and SEC-CSRF-03 (regenerate at password and token login, not on the Bearer bridge, rotated token in the login response, logout clears it). Implements D-01, D-02, D-03, D-04, D-08 and the three-state mode of D-17.
Output: reworked `lib/middleware/csrf.js`, new `lib/thinx/establish_session.js`, login/logout wiring in `lib/router.auth.js`, `assertReady()` in `thinx-core.js`, a new local flow spec and the rewritten unit spec. Nothing is pushed in this plan.
</objective>

primary_noun: the anti-CSRF token's trust anchor (what a valid XSRF-TOKEN is bound to)
transition: singular to plural. The cookie-only double-submit token becomes one of three CSRF_MODE states, alongside the session-bound signed token and the observe stage between them.
