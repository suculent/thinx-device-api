Production conventions (Phase 27 precedent, written into the runbook by Task 1):
- **ssh.** `MICRO_SSH` stands for the literal manager ssh command from AGENTS.md § Deployment plus `-o BatchMode=yes -o ConnectTimeout=10`, typed in full at run time (memory `micro-ssh-direct-form`), never wrapped in a variable or function and never written into a committed file. `CORE_SSH` is the `core` entry from `~/.aliases`. One ssh host per Bash call. A permission-classifier denial becomes a `checkpoint:human-action` carrying the exact command.
- **Services.** Query placement first (`docker service ps <svc> --filter desired-state=running`); `docker exec` is node-local. Select containers by `label=com.docker.swarm.service.name=<svc>`. Query services by name; `docker service ls` returns unstable subsets under load.
- **Output.** Aggregates only: counts, sizes, 12-hex digest prefixes, RFC3339 times. Never registry credentials, user hashes, the CouchDB admin hash, IPs or tokens.
- **Waiting.** No foreground sleep. Use a bounded remote until-loop inside the ssh command, a background Bash command, or the Monitor tool.
- **Signing.** Commits are GPG-signed. If signing fails because the agent is locked, stop before pushing and return a `checkpoint:human-action` (unlock gpg, or grant an explicit push-unsigned exception as in Phase 27, recorded as `p28_unsigned_exception=<reason>`). That is NO-MEASUREMENT, never a gate failure.
- **Tokens.** Annex tokens are `key=value` and appear exactly once in the runbook. Outside the Annex, name a token without its `=` sign.
</context>
