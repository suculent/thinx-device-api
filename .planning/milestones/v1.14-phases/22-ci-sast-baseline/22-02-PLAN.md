Facts verified at planning time (2026-09-25; re-verify, do not trust blindly):
- **Chain already works live.** `https://console.thinx.cloud/js/app.js` contains `consoleHostname = "console.thinx.cloud"`. The value has no scheme, and `fixUrlProtocol` at hostnames.js:16-18 turns it into `https://console.thinx.cloud`. The bundle's buildHash is `115acff`, which is CircleCI job 15391 (`vue-console-registry`, thinx-staging, success). That job's required-vars step printed `All required environment variables are present.`
- The bundle is a development-mode webpack build with eval'd modules, so string literals appear with escaped quotes (`\"`). The grep patterns below use `\W*` to absorb them.
- **Producer pipeline.** The parent `.circleci/config.yml` job `vue-console-registry` builds the deployed Vue image on `thinx-staging`, with contexts dockerhub, thinx-docker-repo and console. The submodule's own `services/console/.circleci/config.yml` job `vue` builds only on branch `thinx-console`. Both jobs declare the `console` context, which is where `VUE_WEB_HOSTNAME` most likely lives. No CircleCI token exists locally. The public v1.1 API is readable without one.
- **Dockerfile.** `ARG VUE_APP_CONSOLE_HOSTNAME` is on line 23 and `ENV` on line 44. `yarn build` is on **line 77**, inside the `RUN bash -c '…'` at lines 66-78. PATTERNS and the orchestrator note said line 76 / 65-77, which is off by one. The checks below compute the line numbers rather than trusting either figure.
- **Router** is hash mode (`vue/src/Routes.js:32`), with public routes `/login` and `/password-reset` and the authenticated `/app`. Headless Chrome (`/Applications/Google Chrome.app`) with `--dump-dom --virtual-time-budget=15000` renders the public pages. Both returned `href="https://console.thinx.cloud"` for the THiNX Console anchor.
- **Swarm.** The classic service is `thinx_console`. It was running on node `core` at planning time, but placement floats, so query it. Its UpdateStatus was `completed`, and its live env includes `VUE_APP_CONSOLE_HOSTNAME`. `thinx_vue` does not carry it.
- **Gluster.** Stack files in `/mnt/gluster/deployment/swarm/` are downtime, errorpage, landing, registry, swarmpit, thinx, traefik and vault `.yml`. Only `thinx.yml` contains the var, at line 290 inside the `  console:` service.
- **SSH.** `micro` is a **shell alias** in `~/.aliases`, not an ssh Host, so `ssh micro` does not resolve from a non-interactive shell. Load the command into the positional parameters with `set -- $(sed -n "s/^alias micro=[\"']\(.*\)[\"']$/\1/p" ~/.aliases) && test "$1" = ssh`, then run `"$@" -o BatchMode=yes -o ConnectTimeout=10 '{remote cmd}'`. This works in both bash and zsh (verified 2026-09-25). Do not keep the command in a plain variable used in command position, because zsh will not word-split it. `micro` is a swarm manager. Do not copy host, port or key into any committed file: this repo is public.
- Memory rules. Never run `restart.sh` or `docker stack deploy`, because both reset the chronograf password. Use `docker service update` for one service. `docker service ls` is unreliable under load, so query services by name. `docker exec` is node-local and is not needed here.
